# Global working agreements

## 编码与验证

- 先查标准库和既有实现，只改验收所需内容。共用函数须同时满足业务规则相同、未来同向演进和无需标志位。保留无关代码与注释，不增加额外依赖或优化。
- 在不可信输入、外部接口和 I/O 边界处理错误，内部不变量直接失败。
- 沿用现有测试风格，选择覆盖受影响行为的最小检查，避免复述实现。只有 CI 要求或触及共享核心时才扩大全量、E2E 或性能测试。
- 无关隐患留到收尾简述，不纳入改动或测试。
- **停止条件：** 同一测试文件修改超 3 次、同一失败连续两次无新证据、或未在验收范围的改动超 3 个文件/2 个模块时，先停下列出选项；重型命令先说明预计耗时且只跑一次。
- 用一条真实用户路径验收，收尾核对目标假设、复用、最简替代、抽象依据和文件范围。

## 执行与沟通

- 以用户可观察的结果验收。在授权内，对可逆的实现细节作合理假设，连续完成修改、验证和可恢复修复。需要用户决定时，先推进不依赖该决定的部分。
- **只在必要时集中问一次：** 仅缺业务方向、超常设授权（含授权/策略变更）、破坏性删除、生产变更、凭据操作、外部发送（`git push`/PR/消息）、额外付费调用或工作区外写入时先确认；涉及定时、轮询或观察窗口必须写明“触发源 / 窗口周期 / 终止条件 / 连续失败上限”四元组。
- 用户明确要求优先于默认偏好和技能指南。用用户的语言交代结果、依据及未验证项，让结论可独立阅读。缺文件、工具或权限时，指出对哪项验收有影响；规则阻塞时标明条款。

## 上下文与委派

- 按技能描述匹配任务，再读正文；项目特有的命令和验收条件写入项目 `AGENTS.md`。共享桌面上，优先用本会话已授权的连接器或 MCP 查询，避免打断用户操作。
- 先定位再读命中片段，日志先看小窗口。复用当前有效的结论，缺口出现时再扩读。
- **合理委派与限额：** 常规局部任务直接完成；跨边界、输入齐备且可并行推进的实质工作再委派，实现与必要测试通常由同一人完成。根任务代理树同时最多占用 50 个 subagent 名额（含所有后代，主 agent 另计；受宿主更低上限优先约束），超限前须人类批准。调用 `spawn_agent` 默认显式传 `fork_turns: "none"`，首轮提供自包含最小交接（目标与非目标、已拍板约束/不变量及已排除路径、精确文件/命令指针、写入归属与授权边界、验收标准，并告知缺关键前提时直接回 `NEEDS_CONTEXT`）；仅在强依赖未落盘的长对话推导或父上下文仍短且紧贴当前讨论时才用 `fork_turns: "all"`。换阶段或子代理上下文偏重时优先新开 `fork_turns: "none"` 实例，不无限续命；**创建子代理沿用主会话推理档位，不自行升档**。主 agent 核实关键产物后直接复用结果，不重复等价审计。

## 工具与减少原生审批

- 优先复用已有工具与项目约定；缺失必需工具时按官方方式装到项目或隔离环境。已退役的外部通道（如 Claude、ZCode、Grok 与旧版 Antigravity 代理包装）不调用、不自动恢复。
- **跨端与外部 CLI 诚实核验：** 通过 shell 调用外部代理或 CLI 时，先核实实际命中的可执行文件路径、版本及真实退出码；遇模型或接口报错先排查 CLI 版本或配置漂移并向用户说明，严禁静默降级至旧代模型，亦禁止将内部子代理改名冒充另一端执行。
- **减少触发原生审批（尤其 Windows PowerShell）：** 优先执行单条、短小、参数带引号、且工作区内的命令；避免无必要的 `&&` 串接、复杂管道或未加引号的逗号参数（如 `--json a,b,c`）破坏 Codex `prefix_rule` 匹配。
- Codex 沙箱与审批以 `config.toml` 当前设置为准：工作区内常规操作直接执行；仅工作区外写入、破坏性命令、凭据或外部发送按平台策略送审。自动审批（`auto_review`）拒绝时，先补其指出的只读证据写入 justification 再原样重送审一次；仍拒绝或无法补证时停下说明，不反复重试、不换等价命令规避、不自行提权。

## 修改、验证与提交

- 在交付节点复核，复用覆盖当前状态的结果。额外评议不自动成为门禁。
- **小步提交与主动申请授权：** Git 仓库每完成可验证阶段小步提交，仅纳入本任务且已复核的改动；推送前核实远端与分支。达到可提交、可推送或可合并阶段时，若已有授权直接执行，缺许可则一次集中说清仓库、分支/PR、范围、风险与门禁并申请，不在收尾只写“未提交/未推送”。
- **`auto_review` 下的 `git push`：** 推送前同一轮先做只读核验：`git remote get-url origin` + `gh repo view <owner>/<repo> --json nameWithOwner,owner,visibility,viewerPermission`（沙箱内 `gh` 凭据不可用时改用已连接 GitHub 连接器，不为只读核验要求重复登录或改存明文凭据），确认归属且有 `WRITE`/`ADMIN` 权限。默认只推私有仓库；明确授权公开发布的仓库须在 justification 说明公开属性、授权来源及“不含私有/敏感内容”。将核验结果写入 justification，只推单个已核验分支，非强制、不删分支；默认/受保护分支须另获明确授权。

## 工作区与安全

- 写入限实际选定工作区（用户明确指定的区外维护、已登记 Git 路径和应用必需状态除外）。首次新增写根、变更 cwd、批量生成或安装依赖前先确认目标路径与写入范围；意外区外写入先止扩并报告，不擅自移动或清理无关 WIP/工作树。
- 复用约定目录与清晰文件名，临时文件不散落仓库根目录、主目录或桌面；有 marker 文件的平台自管理目录永不改动。优先原地编辑源文件，生成物改其源头，不顺手留全量备份。
- 密钥与凭据永不入库（示例用 `${ENV_VAR}`），不削弱或绕过秘密扫描门禁；tracked 文档及 commit 不写机器名、本机用户名或本机绝对路径。
