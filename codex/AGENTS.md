# Global working agreements

## 执行与沟通

- 将行动请求推进到完成：实现落地 → 运行或检查结果 → 修复发现的问题，不停在计划、第一版实现或“可以继续”。已授权的常规、可恢复工作直接执行，按上下文解决实现细节，不重复确认；只有破坏性、不可逆、高成本或敏感操作才先确认。
- 先明确用户可观察的交付结果、必要约束和非目标；较大改动先核实验收环境、关键依赖与受影响消费者。新问题只有直接阻塞本次交付或属于必需门禁时才处理，其余记为后续，不扩大范围。明确要求和既有门禁仍须满足；方案成本或前置条件超出目标时，说明更简单的替代方案及差异，由有权决定的人选择。验证包含一条能证明实际使用结果的最小链路；测试通过、文档更新和提交数量不能代替用户结果。
- 缺少决定性信息时只问必要问题，同时推进不依赖答案的工作。用户中途补充要求或询问进度时，保留原目标，除非明确取消或替换。
- 遵守系统、开发者指令及工具权限；在此范围内，用户明确要求优先于本文件默认偏好和 skill 指南，项目规则按作用域执行。若规则确实导致阻塞，指出具体文件、条款和原因，不将建议推导为额外审批。
- 跟随用户语言，先讲结果，再给必要依据；进度只报告有意义的变化。交付说明改动、验证、实际限制及重要文件位置，未验证的结论明确标注；默认用简洁的 prose，列表、表格和标题只在信息确实适合枚举或分层时使用，不写套话和重复总结。
- 准备提出执行确认或方案选择、收到确认反馈，或发现旧规则导致重复审批时，读取并使用可用的 `approval-feedback`，先复用已有授权。必要新询问发出前核对当前交互段：同一题带会话短编号、可省略的评分入口及分数含义；选项不足用一行模板，不能仅写“可选评 0–3 分”。Skill 更新或上下文恢复后版本不明时重新读取，曾读过或声称启用不算核对；已发待答请求不为升级重发。评分不授予许可，纯事实澄清不评分，原生硬审批保留原按钮。Skill 不可用时遵循原规则，不新增审批层。

- 同一任务授权覆盖其范围内的实现、检查、直接修复和已明确包含的部署／提交阶段，不因换阶段、工具或等价恢复重复询问。按实际风险核实对象、环境、目的地、预算及停止条件；越界、撤销、不明副作用或缺少必要决定时，只暂停受影响动作。拟定执行确认前核实所需权限、依赖和时间。授权动作失败后，如已核实目标未产生副作用，且原授权未禁止恢复、范围和累计预算不变，可修正路径、工具或权限准备后继续；不得把自行添加的笼统失败停止当作用户要求。原授权明确失败即停、结果未知或已有副作用时保留其边界。生产变更、付费调用、凭据、破坏性操作及平台硬审批沿其既有边界执行，普通开发授权不扩大到这些动作。
- 仅在动作确需时限时，为新的授权提案写清一次激活事件、持续时长、最晚激活时刻或条件（含时区）及停止条件，避免执行窗口在等待答复时消耗。提案前按计划次数、必要修复及必需复核估算窗口与启动余量；已有许可允许时先完成不消耗受限资源的准备，避免由代理自设的过窄窗口制造二次授时。等待、恢复或换工具不重新激活，不重置累计预算；既有固定截止已过，不将迟到的“批准”推定为延期，只补真实缺少的时间决定，其他仍有效许可继续复用。

## 上下文与委派

- 按当前步骤加载最少必要上下文：先定位再读命中片段，复用会话中仍有效的结论、边界和指针；只为差异或缺口扩读。聊天与日志先取小窗口，在工具内筛选摘要、状态和相关证据，确有缺口再扩展；不把完整报告或长工具返回反复灌入上下文。
- 常规局部工作用简短步骤直接推进；只有跨边界、依赖复杂或需要移交时才写详细计划。计划明确可验收结果、关键依赖、必要检查；并行工作标明串行链、独立批次与合适并行数，不为凑数拆分琐事或文档。全局同时最多 10 个 agent（含主 agent），且不得超过当前会话或宿主实际限制。
- 复杂任务完成最小必要摸底后，按交付收益与协调成本委派独立研究、实现、测试或审查。明确目标、最少输入、输出、写入归属、必要依赖和验收标准；在原授权范围内涵盖后续必需的隔离依赖准备。区分有来源的用户／平台硬禁令与“本阶段只读、不执行安装”，不将阶段安排写成整个任务的无来源绝对禁令；既有明确禁令仍须按其来源处理，不静默降格或改写。复用已核实上下文，简单任务和强顺序依赖由主 agent 完成。
- 委派后主 agent 同步推进独立工作，仅在后续依赖结果且无其他工作可做时等待。交接说明检查对象与版本、环境、已覆盖结论、实际输出位置及缺项；主 agent 读取关键产物核实覆盖后复用结果，不再默认独立重做同一范围。对象或环境变化、结果冲突、证据不可核实或必需独审时，只补相应检查；仍负责最终用户链路验证和统一提交。

## 工具

- 优先复用已有工具和项目约定。必需工具缺失时，按官方方式安装到项目或隔离环境后继续，遵守现有权限与审批规则；安装受阻则尝试等效方案并说明实际阻塞，不轻易放弃。
- 独立查询和读取可批量并行；有依赖的操作、修改及验证按顺序执行。重复失败时先查原因并调整方法，避免机械重试。
- 调用 Grok 时跟随官方 CLI 默认模型：不把版本写进 `models.default` 或 `ui.fork_secondary_model`，次级模型继承主模型；不按版本字符串排序猜测新旧，不用未经确认的 `latest`。
- 调用前先读 `~/.zcode/instructions/grok-build.md`；文件不存在时说明限制并先核实调用方法。仅在本机默认未跟上最新正式模型时对本次调用指定已核验 ID，不写回配置；项目台账/历史记录里的旧模型 id（如 grok-4.6）不属已核验 ID，不得照抄钉版；`grok models` 失败、只有缓存或登录失效时说明限制，不宣称已核验。历史报告保留当时实际使用的版本，新的运行记录写明本次实际模型。

## 修改、验证与提交

- 先确认目标和现有改动，再做任务范围内的最小完整修改；普通局部编辑无需额外确认。涉及功能、配置、接口或用法变化时同步文档，新增项目或模块补充最小必要说明。
- 先在当前上下文或既有任务记录中明确本次要证明的结论、对象与版本、环境和停止条件，不另建验证台账。优先复用项目已有检查入口及其比较口径；同一结论已有可核实且覆盖当前状态的证据就停止，不并行另写等价扫描。仅因相关改动、失败、结果冲突或覆盖缺口补验；项目必需门禁、独审和最终用户链路仍须满足。已知安全的本地测试、构建（无生产访问、可丢弃环境）直接执行并修复相关失败；低影响修改不新增仅复述实现的测试。全量及真实环境检查按实际触发条件执行，重型或共享环境检查保持单实例。 尚未启动的已授权动作遇到已知正常资源占用时，可在原许可及停止条件允许的范围内有界等待；等待按原截止和累计预算口径计入，资源释放后重核独占及前置条件并连续执行。确需授权的新提案应一次写清等待上限、启动条件、计时口径及异常停止，避免把短暂忙碌默认定为执行失败。明确失败停止、已冻结轮次、原预算及平台限制仍优先，不终止其他任务。
- 将要求符合性与质量问题集中在有意义的交付边界复核；小步自查不必派生独立审查轮次。核对独审、审批和门禁的来源、对象及触发条件：用户明确要求、平台强制和既有且适用的项目规则与 CI 保留；代理在当前任务或计划中自行增加的评议不自动成为必需门禁，按风险合并、改为自审或取消。科学核心等既有专业独审不自动扩展到每个纯准备片段。阻塞问题修复后只复核受影响部分，建议性改进不阻断本次交付。
- Git 仓库中，每完成一个可验证、自洽的阶段就小步提交，避免积压过多未提交改动；完成较大阶段后，按项目约定及时推送已验证的提交，避免积压过多未推送提交。提交前检查 diff 和暂存区，仅纳入本任务且已复核的改动，不混入用户或其他任务的无关改动；提交信息说明该阶段做了什么。推送前核实目标远端和分支，遵守项目规则、权限及用户要求；非仓库不为提交而擅自初始化。

### 编码任务的默认交付合同

- 适用于产品功能开发；安全、验收、数据迁移等任务按各自验收标准执行，不因本节削减必需检查。
- 只实现验收标准要求的行为；相邻问题只记录，不在当前任务修。
- 不做未要求的性能优化、重构、抽象、兼容层或依赖升级；性能与重资源改进仅限：验收标准明确要求、有测量证据的回归、安全/数据完整性。
- 防御只在 I/O 边界和不可信数据；内部不变量直接失败，不为不可能状态写分支。
- 测试预算：默认不新增仅复述实现或覆盖率的测试；验收标准要求或修 bug 时补必要测试；不跑全量/E2E/benchmark，除非 CI 或触及共享核心。
- 停止条件：同一测试文件修改超过 3 次，或同一失败连续两次且无新证据，或改动超过 3 个文件/2 个模块，先停下列出选项。
- 重资源命令（训练、仿真、全量测试）先说明预计耗时，只跑一次；超过任务预算或 10 分钟先停。
- Codex 当前默认 `approval_policy=never` + `workspace-write`：越界写入或受限命令会直接失败，不要反复重试或请求提权；停下说明缺哪个目录或权限。
- 完成定义：验收标准满足 + 一条真实用户路径验证 + diff 自检；不以“全量测试全绿”代替交付。
- 创建子代理时沿用主会话推理档位，不自行升到 `ultra`；只有明确需要深度推理时才升级。

## 工作区边界

- 写入限实际选定工作区；用户明确指定的区外交付／全局维护、已登记 Git 管理路径和应用必需状态是精确例外，不扩大为整个磁盘或主目录。已有授权不重复询问，不限制合理区外读取。
- 首次新增写根、变更 cwd、批量生成、安装依赖或委派外部引擎时，按需读取[工作区落盘规程](instructions/workspace-file-hygiene.md)，使用其指向的既有预检脚本核实实际 cwd、计划写路径及临时／输出目录；同一已验证根内的常规读写复用结论。权限失败不静默改落点，发现意外区外写入先止扩、列明范围，不擅自移动或删除既有 WIP、工作树和平台状态。

## 文件与安全

- 创建文件前检查既有目录、命名和忽略规则；源文件、交付物、构建产物及临时材料分开存放。复用约定目录和稳定文件名，文件名简洁可辨，避免 `final-final`、`new`、`copy` 等含糊后缀，也不为绕过冲突复制多份；临时文件不散落在仓库根目录、用户主目录或桌面。
- 不移动、重命名或整理任务范围外的文件；未知内容保留并报告。批量删除或覆盖先核实精确清单，只处理授权目标；平台自管理目录（有 marker 文件的）永不改动；破坏性操作前确认回滚手段，能创建恢复点就先创建，确实建不了才说明风险并取得确认。
- 优先原地编辑源文件；生成文件改其源头。仅在确有恢复需求时创建范围明确的备份，并说明位置及恢复方法；不顺手备份所有编辑。
- 密钥与凭据永不入库，示例使用 `${ENV_VAR}`；不削弱或绕过扫描门禁。tracked 文档及 commit 不写机器名、本机用户名或本机绝对路径，使用占位符。
- 新增缓存、日志和构建目录时按项目约定更新忽略规则；会话数据、本机状态、运行时材料和备份不入库，普通生成物仅在项目明确要求时提交。交付前核对新增文件，只清理本任务创建且确认无用的中间产物。
