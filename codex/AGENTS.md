# Global working agreements

## 编码与测试底线（优先执行）

- **外科手术式最小改动：** 只实现验收标准要求的行为；禁止顺手重构、格式化或改写无关代码与注释。不新增未要求的性能优化、抽象层、兼容胶水或依赖。
- **克制防御性编程：** 只在不可信输入、外部接口与 I/O 边界做校验和错误处理；内部不变量直接失败，不为不可能状态写冗余判空、兜底分支或吞错 `try/catch`。
- **严控测试与回归范围：** 默认不新增仅复述实现、测 trivial 细节或覆盖率凑数的单测；需要补测试时沿用附近既有测试风格，不自造新 Mock 层或测试脚手架。**禁止每次小改动后自动运行全量/E2E/benchmark 套件**（除非 CI 要求或触及共享核心），只跑受影响目标的最小验证。
- **风险只列不改：** 顺带发现的无关隐患、代码异味或额外边界情况，只在回复末尾简要列出，**不要写进本次 diff 或新增测试**。
- **停止条件：** 同一测试文件修改超 3 次、同一失败连续两次无新证据、或未在验收范围的改动超 3 个文件/2 个模块时，先停下列出选项；重型命令先说明预计耗时且只跑一次。
- **完成定义：** 验收标准满足 + 一条真实用户路径验证 + diff 自检；不以“全量测试全绿”代替交付。

## 执行与沟通

- **直接推进到完成：** 已授权任务范围内的读取、编辑、构建、局部测试及明确可恢复的准备/修复连续推进，不为常规工作区操作、换阶段、换工具或修正明确命令错误发文字确认。
- **只在必要时集中问一次：** 仅破坏性删除、生产变更、凭据操作、外部发送（`git push`/PR/消息）、额外付费调用、工作区外写入或缺少决定性需求时先确认。可用 `approval-feedback` 时先复用已有授权；确需非原生确认或方案选择时，按其当前交互格式带会话短编号与可选 `0–3` 评分合并问一次。收到 `0/1` 分或重复阻塞反馈时立即按其双轨流程处理；原生硬弹窗保留原按钮，不以低分自动授权。
- **明确结果与简洁汇报：** 用户明确要求优先于本文件默认偏好和 skill 指南；规则确实阻塞时指出具体文件、条款和原因。跟随用户语言，先讲结果与关键依据，未验证结论明确标注，不写套话与重复总结。

## 上下文与委派

- **按需取上下文：** 先定位再读命中片段，复用会话内仍有效的结论与指针；日志和命令输出先取小窗口摘要，缺口时再扩读。
- **合理委派与限额：** 常规局部任务直接完成；跨边界、输入齐备且可并行推进的实质工作再委派，实现与必要测试通常由同一人完成。根任务代理树同时最多占用 50 个 subagent 名额（含所有后代，主 agent 另计；受宿主更低上限优先约束），超限前须人类批准。首轮只交接目标、写入归属、依赖、授权边界和验收标准；**创建子代理沿用主会话推理档位，不自行升档**。主 agent 核实关键产物后直接复用结果，不重复等价审计。

## 工具与减少原生审批

- **Gemini 的含义：** 用户说“gemini”或要求“呼叫 gemini”时，指 Gemini 订阅提供的模型和额度，其中包括 **Claude Opus 5.5 High**。通过该订阅渠道使用 Claude 符合这一要求，无须仅因模型属于 Claude 再次确认；执行记录仍如实注明实际模型。
- 优先复用已有工具与项目约定；缺失必需工具时按官方方式装到项目或隔离环境。Grok 仅在用户明确点名时通过 `agent-bridge` 调用，不回退本地 CLI 直连。
- **减少触发原生审批（尤其 Windows PowerShell）：** 优先执行单条、短小、参数带引号、且工作区内的命令；避免无必要的 `&&` 串接、复杂管道或未加引号的逗号参数（如 `--json a,b,c`）破坏 Codex `prefix_rule` 匹配。
- Codex 沙箱与审批以 `config.toml` 当前设置为准：工作区内常规操作直接执行；仅工作区外写入、破坏性命令、凭据或外部发送按平台策略送审。自动审批（`auto_review`）拒绝时，先补其指出的只读证据写入 justification 再原样重送审一次；仍拒绝或无法补证时停下说明，不反复重试、不换等价命令规避、不自行提权。

## 修改、验证与提交

- **交付边界复核：** 将自查集中在有意义的交付边界，不因小步改动派生独立审查轮次；代理自增的评议不自动成为阻塞门禁。同一结论已有覆盖当前状态的实证就停止，不并行另写等价扫描。
- **小步提交与主动申请授权：** Git 仓库每完成可验证阶段小步提交，仅纳入本任务且已复核的改动；推送前核实远端与分支。达到可提交、可推送或可合并阶段时，若已有授权直接执行，缺许可则一次集中说清仓库、分支/PR、范围、风险与门禁并申请，不在收尾只写“未提交/未推送”。
- **`auto_review` 下的 `git push`：** 推送前同一轮先做只读核验：`git remote get-url origin` + `gh repo view <owner>/<repo> --json nameWithOwner,owner,visibility,viewerPermission`（沙箱内 `gh` 凭据不可用时改用已连接 GitHub 连接器，不为只读核验要求重复登录或改存明文凭据），确认归属且有 `WRITE`/`ADMIN` 权限。默认只推私有仓库；明确授权公开发布的仓库须在 justification 说明公开属性、授权来源及“不含私有/敏感内容”。将核验结果写入 justification，只推单个已核验分支，非强制、不删分支；默认/受保护分支须另获明确授权。

## 工作区与安全

- 写入限实际选定工作区（用户明确指定的区外维护、已登记 Git 路径和应用必需状态除外）。首次新增写根、变更 cwd、批量生成或安装依赖时，按需读取 [工作区落盘规程](instructions/workspace-file-hygiene.md) 并先跑其预检脚本；意外区外写入先止扩并报告，不擅自移动或清理无关 WIP/工作树。
- 复用约定目录与清晰文件名，临时文件不散落仓库根目录、主目录或桌面；有 marker 文件的平台自管理目录永不改动。优先原地编辑源文件，生成物改其源头，不顺手留全量备份。
- 密钥与凭据永不入库（示例用 `${ENV_VAR}`），不削弱或绕过秘密扫描门禁；tracked 文档及 commit 不写机器名、本机用户名或本机绝对路径。
