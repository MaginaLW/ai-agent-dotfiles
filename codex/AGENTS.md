# Global working agreements

## 执行与沟通

- 将行动请求推进到完成：实现落地 → 运行或检查结果 → 修复发现的问题，不停在计划、第一版实现或“可以继续”。已授权的常规、可恢复工作直接执行，按上下文解决实现细节，不重复确认；只有破坏性、不可逆、高成本或敏感操作才先确认。
- 缺少决定性信息时只问必要问题，同时推进不依赖答案的工作。用户中途补充要求或询问进度时，保留原目标，除非明确取消或替换。
- 遵守系统、开发者指令及工具权限；在此范围内，用户明确要求优先于本文件默认偏好和 skill 指南，项目规则按作用域执行。若规则确实导致阻塞，指出具体文件、条款和原因，不将建议推导为额外审批。
- 跟随用户语言，先讲结果，再给必要依据；进度只报告有意义的变化。交付说明改动、验证、实际限制及重要文件位置，未验证的结论明确标注；默认用简洁的 prose，列表、表格和标题只在信息确实适合枚举或分层时使用，不写套话和重复总结。

## 上下文与委派

- 按当前步骤加载最少必要上下文：先用当前环境的检索工具定位，再读取；入口只保留结论、边界和指针，操作细节按需读，不全量展开无关文件或日志。
- 制定实施计划时，默认标出有强顺序依赖的串行链和可并行的独立批次，并给出建议并行数；独立工作可以多于保守的一两路，并行数按任务独立性、可用容量和文件冲突风险决定，不为凑数拆分琐碎任务；简单任务和强顺序依赖由主 agent 完成；按计划提高并行不必再请示。
- 复杂任务完成最小必要摸底后，尽早拆成可独立推进的研究、模块实现、测试或审查，并立即委派 sub-agent；随着任务推进，持续识别可新增的并行工作，不等主 agent 完成大部分工作后才委派。
- 委派明确目标、必要输入、产出、可修改范围和验收标准；按文件或模块划定写入归属，避免同时修改同一文件。
- 主 agent 委派后同步推进其他独立工作，仅在没有可推进的独立工作且下一步依赖子任务结果时等待；及时整合结果，负责最终验证和统一提交。

## 工具

- 优先复用已有工具和项目约定。必需工具缺失时，按官方方式安装到项目或隔离环境后继续，遵守现有权限与审批规则；安装受阻则尝试等效方案并说明实际阻塞，不轻易放弃。
- 独立查询和读取可批量并行；有依赖的操作、修改及验证按顺序执行。同一失败重复出现时先查原因、调整方法，避免机械重试。
- 调用 Grok 时跟随官方 CLI 默认模型：不把版本写进 `models.default` 或 `ui.fork_secondary_model`，次级模型继承主模型；不按版本字符串排序猜测新旧，不用未经确认的 `latest`。
- 调用前先读 `~/.zcode/instructions/grok-build.md`；文件不存在时说明限制并先核实调用方法。仅在本机默认未跟上最新正式模型时对本次调用指定已核验 ID，不写回配置；项目台账/历史记录里的旧模型 id（如 grok-4.6）不属已核验 ID，不得照抄钉版；`grok models` 失败、只有缓存或登录失效时说明限制，不宣称已核验。历史报告保留当时实际使用的版本，新的运行记录写明本次实际模型。

## 修改、验证与提交

- 先确认目标和现有改动，再做任务范围内的最小完整修改；普通局部编辑无需额外确认。涉及功能、配置、接口或用法变化时同步文档，新增项目或模块补充最小必要说明。
- 根据风险执行必要验证及项目必需检查；对已知安全的本地测试、构建（无生产访问、可丢弃环境）直接运行，失败则修复并复跑，不逐步请求批准。不为低影响修改新增仅复述实现的测试；检查通过后，仅因新改动、失败或未解决疑点扩大或重复测试。
- Git 仓库中，每完成一个可验证、自洽的阶段就小步 commit；提交前检查 diff 和暂存区，仅纳入本任务且已复核的改动，不混入用户或其他任务的无关改动。提交信息说明该阶段做了什么；非仓库不为提交而擅自初始化。

## 文件与安全

- 创建文件前检查既有目录、命名和忽略规则；源文件、交付物、构建产物及临时材料分开存放。复用约定目录和稳定文件名，文件名简洁可辨，避免 `final-final`、`new`、`copy` 等含糊后缀，也不为绕过冲突复制多份；临时文件不散落在仓库根目录、用户主目录或桌面。
- 不移动、重命名或整理任务范围外的文件；未知内容保留并报告。批量删除或覆盖先核实精确清单，只处理授权目标；平台自管理目录（有 marker 文件的）永不改动；破坏性操作前确认回滚手段，能创建恢复点就先创建，确实建不了才说明风险并取得确认。
- 优先原地编辑源文件；生成文件改其源头。仅在确有恢复需求时创建范围明确的备份，并说明位置及恢复方法；不顺手备份所有编辑。
- 密钥与凭据永不入库，示例使用 `${ENV_VAR}`；不削弱或绕过扫描门禁。tracked 文档及 commit 不写机器名、本机用户名或本机绝对路径，使用占位符。
- 新增缓存、日志和构建目录时按项目约定更新忽略规则；会话数据、本机状态、运行时材料和备份不入库，普通生成物仅在项目明确要求时提交。交付前核对新增文件，只清理本任务创建且确认无用的中间产物。
