## Known boundaries

- **Codex global agreements use a managed block.** `codex/AGENTS.md` is canonical; the live Codex file wraps it in `<!-- BEGIN/END AI-AGENT-DOTFILES: codex/AGENTS.md -->` markers, preserving outside local content.
- **Combined deploy is not atomic.** Skills and config stages share one command and authorization boundary, not a transaction; config failure leaves completed skill changes in place.
- **Primary checkout is single-writer.** Parallel agent work uses throwaway worktrees and integrates serially; one full local validation run at a time ([AGENTS.md](AGENTS.md)).
- **Privacy history rewrite & old clones.** An exact-path rewrite redacted the initial 82 commits (`dd4014f` first rewritten commit; server GC completed). Clones resolving pre-rewrite SHAs must export unique work and re-clone ([docs/HISTORY.md](docs/HISTORY.md)).
- **Deploy state is per machine.** `deploy-skills` prunes only directories in its state file; directories from an older setup show as `unknown` until `-Retire` names them.
- **Codex catalog refresh and loaded skill bodies.** Codex detects changes automatically (restart if needed); an already-loaded conversation retains prior `SKILL.md` or `AGENTS.md` text until reloaded.
- **Antigravity live deploy under an open IDE on Windows.** Running `antigravity deploy -Apply` while Antigravity IDE is open can fail with Windows `Access is denied` when `agy plugin install` renames into `~/.gemini/config/plugins/`. Close Antigravity IDE and run recovery/deploy from an external PowerShell 7 window ([docs/README.md §15](docs/README.md#15-antigravity-插件)).
- **Out of scope.** Whole Codex `config.toml`, private `.env` files, credentials, sessions, and caches are outside `config-sync` (only per-entry managed MCP projection under `AGENTS.md` hard rules is permitted); `tmp/` and private roots are never committed.
