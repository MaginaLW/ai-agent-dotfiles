
# Global working agreements

## 编码与验证

- 先查标准库和既有实现，只改验收所需内容。共用函数须同时满足业务规则相同、未来同向演进和无需标志位。保留无关代码与注释，不增加额外依赖或优化。
- 在不可信输入、外部接口和 I/O 边界处理错误，内部不变量直接失败。
- 沿用现有测试风格，选择覆盖受影响行为的最小检查，避免复述实现。只有 CI 要求或触及共享核心时才扩大全量、E2E 或性能测试。
- 无关隐患留到收尾简述，不纳入改动或测试。
- **停止条件：** 同一测试文件修改超 3 次、同一失败连续两次无新证据、或未在验收范围的改动超 3 个文件/2 个模块时，先停下列出选项；重型命令先说明预计耗时且只跑一次。
- 用一条真实用户路径验收，收尾核对目标假设、复用、最简替代、抽象依据和文件范围。

## 执行与沟通

- 授权内的读写、构建、局部验证及可恢复修复连续完成，不为换阶段或常规操作重复询问。
- **只在必要时集中问一次：** 仅缺业务方向、超常设授权（含授权/策略变更）、破坏性删除、生产变更、凭据操作、外部发送（`git push`/PR/消息）、额外付费调用或工作区外写入时先确认；涉及定时、轮询或观察窗口必须写明“触发源 / 窗口周期 / 终止条件 / 连续失败上限”四元组。
- 用户明确要求优先于默认偏好和技能指南。用用户的语言报告结果、依据及未验证项；阻塞时指出具体条款。

## 上下文与委派

- 用户规则和工作区根目录的 `AGENTS.md` 在新任务启动时依次加载。关键项目约束直接写在根文件。技能描述开头写明触发场景，需要时用 `$技能名` 指定；MCP 操作按当前连接核实。
- 先定位再读命中片段，日志先看小窗口。复用当前有效的结论，缺口出现时再扩读。
- **合理委派与限额：** 常规局部任务直接完成；跨边界、输入齐备且可并行推进的实质工作再委派，实现与必要测试通常由同一人完成。全局同时最多 10 个 agent（含主 agent，受宿主更低上限优先约束），超限前须人类批准。首轮只交接目标、写入归属、依赖、授权边界和验收标准；**创建子代理沿用主会话推理档位，不自行升档**。主 agent 核实关键产物后直接复用结果，不重复等价审计。

## 工具与权限边界

- **复用既有能力与默认配额：** 优先复用已有工具、内置能力与项目约定；缺失必需工具时按官方方式装到项目或隔离环境。多模态与自动化调用默认优先使用已有额度，未获显式授权不发起额外付费 API 调用。
- **遵守宿主权限与沙箱策略：** 遵守当前会话与项目的审批、沙箱及网络/区外访问策略；工作区内常规读写、测试和构建直接执行；禁止绕过权限检查、沙箱边界或验证码/反爬验证，拒绝或失败时停下说明原因，不换等价命令规避或自行提权。

## 修改、验证与提交

- 在交付节点复核，复用覆盖当前状态的结果。额外评议不自动成为门禁。
- **小步提交与主动申请授权：** Git 仓库每完成可验证阶段小步提交，仅纳入本任务且已复核的改动；推送前核实远端与分支。达到可提交、可推送或可合并阶段时，若已有授权直接执行，缺许可则一次集中说清仓库、分支/PR、范围、风险与门禁并申请，不在收尾只写“未提交/未推送”。
- **`git push` 前核验：** 推送前先做只读核验（`git remote get-url origin` 及仓库归属/可见性/写权限），确认归属且有写权限；默认只推私有仓库，明确授权公开发布的仓库须确认“不含私有/敏感内容”，只推单个已核验分支，非强制、不删分支，受保护/默认分支须另获明确授权。

## 工作区与安全

- **写入限实际选定工作区：** 写入限实际选定工作区（用户明确指定的区外维护、已登记 Git 路径和应用必需状态除外）。首次新增写根、变更 cwd、批量生成或安装依赖前先确认目标路径与写入范围；意外区外写入先止扩并报告，不擅自移动或清理无关 WIP/工作树。
- **落盘整洁与单一真源：** 复用约定目录与清晰文件名，临时文件不散落仓库根目录、主目录或桌面；平台自管理目录不手改。优先原地编辑源文件，生成物改其源头，不顺手留全量备份。
- **零凭据与隐私入库：** 密钥与凭据永不入库（示例用 `${ENV_VAR}`），不削弱或绕过秘密扫描门禁；tracked 文档及 commit 不写机器名、本机用户名或本机绝对路径。
