# AI Agent Dotfiles

This is a Windows dotfiles repository for Claude Code, Codex and ZCode. It builds
each platform's skills from one shared source tree and deploys a selected set of them to each
machine's live skill directories with one dry-run-first script.

## How it works

- `skills-source/` is the only hand-maintained skill source tree.
- `claude/skills/` and `codex/skills/` are generated by `scripts/build-skills.ps1` and ignored by Git.
- An environment (`harness-source/envs/<name>.psd1`) selects the skills each platform gets.
  `work` is the daily coding, review and research-writing set; `full` selects every managed skill.
- `scripts/deploy-skills.ps1` deploys one environment to the live targets:

  | Platform | Live skills directory |
  |---|---|
  | Claude | `~/.claude/skills` |
  | Codex | `~/.codex/skills`, or the `~/.agents/skills` fallback when only that one exists (having both is rejected as ambiguous) |
  | ZCode | `~/.zcode/skills` (projection: deploys the Claude generated output; no generated root of its own) |

- Deployment handles one skill directory at a time. It prunes only directories it deployed
  itself or that `-Retire` names; unselected unknown directories are left alone. A selected skill
  can update a pre-existing directory with the same name, even if it was previously unknown.
  Codex `.system` (the CLI's built-in skills) is never touched, and no live skills directory is
  ever mirrored wholesale — a bare `robocopy /MIR` would delete `.system` along with every skill
  the repository does not manage.
- Secrets, auth files, sessions, caches and machine-private config such as Codex `config.toml`
  and private `.env` files never enter the repository. Scripts require PowerShell 7+ (`pwsh`).

## New clone

```powershell
$RepoRoot = '<repo-root>'
git clone <repo-url> $RepoRoot
Set-Location $RepoRoot
pwsh -NoProfile -File .\bootstrap.ps1
```

Bootstrap installs and verifies the pinned gitleaks scanner, builds the generated skills and
prints the deploy-skills dry-run command to review next; it never writes a live skills root.
Machine setup: [docs/ONBOARD_NEW_MACHINE.md](docs/ONBOARD_NEW_MACHINE.md).

Tests keep config-sync fixture repo, home and backup trees under the project's ignored
`tmp/tests/config-sync/<run-id>/`. Normal failures save a small pre-cleanup receipt in
`tmp/tests/config-sync/receipts/` before removing generated payload. A timeout or a child
that skips finalization retains its exact owned tree; parent exit and drained output do
not prove every writer stopped. Check actual tree and writer state before cleanup; a
receipt's `cleanup_requested` field records intent, not completed deletion.

## Everyday commands

From the repository root in PowerShell 7+:

```powershell
pwsh -NoProfile -File .\scripts\build-skills.ps1
pwsh -NoProfile -File .\scripts\scan-secrets.ps1
pwsh -NoProfile -File .\scripts\agent-dotfiles.ps1 env list
pwsh -NoProfile -File .\scripts\deploy-skills.ps1 -Environment work
pwsh -NoProfile -File .\scripts\deploy-skills.ps1 -Environment work -Apply
```

`work` is an example; choose the environment you want. Switching to a smaller selection can
plan `prune` operations for skills previously deployed by this tool. Review every planned action
before requesting authorization for Apply.

Without `-Apply`, deploy-skills builds and scans before printing what it would install, update,
prune or leave as unknown. The build may recreate ignored generated output in the repository;
the dry run does not write live skills or deploy state. `-Apply` writes the live home, so it needs
the owner's authorization after the dry run has been reviewed. Before an update or prune it copies
the old directory to a backup outside the repository; restoring is described in
[docs/README.md §8](docs/README.md#8-备份与恢复).

`work` 和 `full` 均包含 [session-learnings](skills-source/shared/session-learnings/SKILL.md)。
部署后在新会话中说“把这次排障中值得复用的经验沉淀到项目文档”，即可按
“适用条件、有效做法、验证依据”整理已验证的发现，优先更新项目现有知识文档。
该单文件 skill 借鉴 [TokenEconomizer](https://github.com/microsoft/TokenEconomizer) 的经验复用思路，
使用当前任务的证据，不安装插件、后台学习或调用额外模型。

同一精简思路也用于 `work` 和 `full` 中的另两项能力：
[systematic-debugging](skills-source/shared/systematic-debugging/SKILL.md) 在相同失败反复出现且没有新证据时，
先归纳失败，再做一次有依据的改路；仍无进展则记录具体阻塞并推进独立工作。
[tool-scope](skills-source/shared/tool-scope/SKILL.md) 在工具密集任务开始时主动确定范围，之后约每 10 次
工具调用自检；阶段切换、调用失败或反复查询同一入口时提前检查。agent 在当前上下文中近似追踪，
复用已有证据，无变化就继续，不必手动输入提示词，也不另外运行扫描或整套测试。
这是 skill 内的任务执行约定，不保证精确计数；不使用定时任务或后台进程，空闲时不运行。
实际关闭能力仍走配置与部署流程，纯 skill 不会自动卸载已加载的工具定义。

## MCP and connected tools

This repository does not register MCP servers or sync Codex `config.toml`. Discover tools in the
current session first: a listed tool does not by itself prove that an account is connected or that
an operation is permitted. Prefer an available service connector for its data; use official sources
for research and technical claims. Check connection and access with an appropriate read-only request
when the task needs them. Do not store tokens, local executable paths or account configuration here.

For OpenAI development questions, use the available OpenAI documentation skill or documentation
search. The [official Docs MCP guide](https://developers.openai.com/learn/docs-mcp) describes an
optional documentation server; adding it changes the user's local configuration and is not part of
this repository's deployment.
