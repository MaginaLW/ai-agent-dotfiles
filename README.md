# AI Agent Dotfiles

Local Windows dotfiles scaffold for Claude Code, Codex, and Reasonix configuration plus shared skill sources.

This repository is intentionally conservative:

- `skills-source/` is the only hand-maintained skill source tree.
- `claude/skills/`, `codex/skills/`, and `reasonix/skills/` are generated by `scripts/build-skills.ps1` and ignored by Git.
- Real secrets, login state, auth files, SSH keys, local caches, and runtime history must never enter the repository.
- Scripts are PowerShell 7+ only. Use the target script's current parameters; public sync resolves identity through its host and does not accept `-HomeRoot`.
- Skill build, secret scanning, manifest-scoped transactions with receipt-backed snapshots, repo-local Git preview hooks, and multi-platform Project Harness outputs are implemented.

## New Clone Bootstrap

Git does not run repository-provided hooks during `git clone`, so each clone must run the
tracked bootstrap entrypoint once:

```powershell
$RepoRoot = '<repo-root>'
git clone <repo-url> $RepoRoot
Set-Location $RepoRoot
pwsh -NoProfile -File .\bootstrap.ps1
```

Bootstrap installs inert/approved Git-private wrappers and checks dependencies in this order:
the pinned JSON Schema validator, pinned gitleaks scanner, then explicit runner approval. If a
dependency or approval is missing, run the exact absolute command bootstrap prints and invoke
bootstrap again. Check [current release and acceptance state](STATUS.md#current-state) before
running bootstrap; hooks produce only non-consumable preview/events and an
explicit external DryRun command. They never create an actionable plan or Apply live changes.

## Deployment Targets (live skills)

When generated skills are deployed to a machine's live agent directories, these rules are authoritative:

- **Claude:** managed skills under `~/.claude/skills` match the reviewed environment selection; unknown directories are preserved.
- **Codex (repo-managed):** managed skills under `~/.codex/skills` (or the claimed fallback) match the reviewed environment selection; unknown directories are preserved.
- **Reasonix:** live skills deploy to `%APPDATA%\reasonix\skills` (`AppData\Roaming\reasonix\skills` under the user profile); `config.toml`, `.env`, sessions, and other machine-private state are never synced.
- **Codex `.system` is protected:** `~/.codex/skills/.system` is the Codex CLI platform-managed skills directory (identified by `.codex-system-skills.marker`, containing built-ins such as `imagegen`, `openai-docs`, `plugin-creator`, `skill-creator`, `skill-installer`). It is **not** a repo-managed skill and **must always be preserved** during sync, cleanup, and prune. It must never be removed as if it were a stale imported skill.
- **No blanket mirror:** deployment/prune must be scoped to entries in `manifests/managed-skills.txt`. Never run a bare `robocopy /MIR` (or equivalent whole-directory mirror) against `~/.codex/skills`, because it would delete `.system` and any other non-managed skills installed by Codex itself.

## Sync & Backup

`sync.ps1` describes deployment to the live skill dirs. Consult the single
[current release and acceptance state](STATUS.md#current-state) before production operations;
policy behavior and release acceptance are separate. The public standalone backup entry is retired:
it writes nothing and exits `backup-is-transaction-internal` instead. Status is read-only;
DryRun can write external plans, materializations and reports for review.
Sync is manifest-scoped (`manifests/managed-skills.txt`), operates one skill dir at a time
(never a whole-dir mirror), and never touches Codex's `.system`.
If a reviewed deletion has already disappeared from the current manifest, the old live
directory remains unknown by default. It can only be removed with an external, one-shot
`-RetireManifestPath` supplied to both the reviewed dry-run and exact apply; auto-sync hooks
never grant that extra deletion authority.

```powershell
# Invocation shape only; check STATUS.md current state and acceptance before use.
# Maintenance validation uses the internal sandbox shape in docs/README.md §4.
# A released bare call may resolve Windows identity and write a plan.
$plan = Join-Path $env:TEMP ('ai-agent-dotfiles-sync-' + [guid]::NewGuid().ToString('N') + '.json')
pwsh -NoProfile -File .\scripts\sync.ps1 -DryRun -PlanPath $plan
```

Plain sync plans only pristine initial deployment; it is not the update route for an
existing authority. Read `canonical status`, then (when canonical-ready) run
`env authority status` in a new invocation and follow its route. For initial deployment,
create the pristine sync plan **before** canonical setup, then complete reviewed setup
and consume the original sync plan in a new invocation. See the
[onboarding route sequence](docs/ONBOARD_NEW_MACHINE.md#5-select-the-machine-route).

The retirement JSON format and deletion workflow are documented in
[`docs/README.md`](docs/README.md#5-修改已有-skill-的流程). The plan binds the resolved
retirement file path and bytes, canonical authority, all source/live roots, and the
reviewed target hashes. Delete the external plan and retirement JSON after a successful
apply; terminal transaction evidence also records consumed document hashes and rejects replay.

## Git Auto-Sync Hooks

Explicit `scripts/setup.ps1 -ApproveRunner -InstallAutoSync` copies only a clean, committed,
policy-allowlisted runner into Git-private versioned storage and installs wrappers that invoke
that approved copy—not checkout scripts. Toolchain drift yields `runner-review-required`.
Data-only changes may create a validated, non-consumable Git-private preview event and print the
external DryRun command. Internal preview paths are never valid public `-PlanPath` values.
