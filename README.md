# AI Agent Dotfiles

This is a Windows dotfiles repository for Claude Code, Codex and Reasonix. It builds each
platform's skills from one shared source tree and deploys them to each machine's live skill
directories through reviewed, plan-bound transactions.

## How it works

- `skills-source/` is the only hand-maintained skill source tree.
- `claude/skills/`, `codex/skills/`, and `reasonix/skills/` are generated by `scripts/build-skills.ps1` and ignored by Git.
- The live targets are:

  | Platform | Live skills directory |
  |---|---|
  | Claude | `~/.claude/skills` |
  | Codex | `~/.codex/skills`, or the `~/.agents/skills` fallback when only that one exists (having both is rejected as ambiguous) |
  | Reasonix | `%APPDATA%\reasonix\skills` |

- Deployment is scoped to the managed manifests (`manifests/managed-skills*.txt`) and handles one
  skill directory at a time. Unknown live directories are preserved.
- **Codex `.system` is protected:** `~/.codex/skills/.system` holds the Codex CLI's own built-in
  skills. It is never synced, pruned or treated as a stale skill.
- Never run a bare `robocopy /MIR` or any other whole-directory mirror against a live skills
  directory. That would delete `.system` and any skill the repository does not manage.
- When a skill is removed from the source, its old live directory remains unknown by default.
  Only an explicit, plan-bound retirement removes it ([docs/README.md §5](docs/README.md#5-修改已有-skill-的流程)).
- Secrets, auth files, sessions, caches and machine-private config such as Codex `config.toml` and
  Reasonix `config.toml`/`.env` never enter the repository.
- Scripts require PowerShell 7+ (`pwsh`).

## New clone

Git does not run repository hooks during `git clone`, so run the bootstrap entrypoint once in
each new clone:

```powershell
$RepoRoot = '<repo-root>'
git clone <repo-url> $RepoRoot
Set-Location $RepoRoot
pwsh -NoProfile -File .\bootstrap.ps1
```

Bootstrap checks its dependencies in this order:
the pinned JSON Schema validator, pinned gitleaks scanner, then explicit runner approval.
If one is missing, run the exact command bootstrap prints and then run bootstrap again.
Approving the runner is a per-machine owner decision, so check the
[current state](STATUS.md#current-state) before running that command. The installed Git hooks only record previews and print an
explicit external DryRun command. They never create an actionable plan or Apply live changes.
Pass `-SkipInitialPlan` to skip the optional initial preview.

## Everyday checks

```powershell
pwsh -NoProfile -File .\scripts\build-skills.ps1 -RepoRoot $RepoRoot
pwsh -NoProfile -File .\scripts\scan-secrets.ps1 -RepoRoot $RepoRoot
pwsh -NoProfile -File .\scripts\check-hooks.ps1 -RepoRoot $RepoRoot
```

## Deploying to a machine

Every plan-bound live change (sync, env, canonical, live recover) follows the same sequence: run a DryRun into a new external `-PlanPath`,
review the plan, then Apply the same plan. The tracked policy being released is not deployment
authorization. Check the [current state](STATUS.md#current-state) and get the owner's
authorization first.

- **First setup of a machine:** [docs/ONBOARD_NEW_MACHINE.md](docs/ONBOARD_NEW_MACHINE.md#5-select-the-machine-route).
- **Machine already set up:** run `scripts/agent-dotfiles.ps1 canonical status`, then
  `env authority status`, and follow the route they print.
- **Rollback and recovery:** [docs/RESTORE.md](docs/RESTORE.md).
