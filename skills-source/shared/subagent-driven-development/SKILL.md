# Subagent-Driven Execution

After the minimum necessary exploration, promptly delegate substantive independent work with sufficient inputs, a clear deliverable and acceptance criteria when it is expected to shorten the critical path, fill necessary coverage or provide valuable independent verification. The lead owns direction, key decisions, integration and final user-visible acceptance.

## Before dispatch

Read the relevant plan or task breakdown once and reuse the existing tracker; do not require a separate planning artifact. Map sequential dependencies and ready independent work. Divide by deliverable feature, module or investigation question; implementation and its necessary tests usually belong to the same executor. When inputs are incomplete, dispatch the parts that do not need them; dependent implementation, final binding and execution wait for the missing decision, without freezing the whole stage.

Do not impose an extra fixed small cap or minimum headcount, or split trivial work to fill capacity. Respect the current host's open/active counting rules and any authorized concurrent allowance shared by the entire root task's descendants, with lower host limits taking precedence. A concurrent allowance does not limit lifetime creation count; stages, context changes and nested delegation do not grant separate allowances or reset native, paid-call or execution-count budgets. Obtain required human approval before exceeding the authorized concurrent limit. Avoid overlapping writes and parallel heavy checks against shared resources.

Give each executor only the outcome, non-goals, minimum inputs, write scope, dependencies, workspace/output boundaries, authorization and acceptance checks needed for its first stage. Share verified facts and label provisional assumptions; do not circulate full exploration notes or copy the full chat. Send consequential changes and next-stage context as they become relevant. Reuse an instance for the same responsibility while its context remains suitable; valuable independent work need not queue behind a busy executor. Use a fresh instance for a new responsibility, required independent review or stale/contaminated context. Reuse established decisions and allocate each check to one owner; do not assign equivalent audits to both lead and worker without an independent-review requirement or concrete risk. Use implementer-prompt.md when useful, adapting it to the actual task.

Include dependencies and necessary isolated preparation in the already-authorized delivery chain. Distinguish owner/platform prohibitions from this stage's actions: a read-only preparation worker can be told "inspect only; do not install in this stage" without inventing a task-wide installation ban. Preserve the source and scope of real prohibitions; do not silently rewrite an existing ban. Missing authority pauses only the affected action, and this guidance grants no paid, credential, production, destructive or new data-transfer permission.

## Execute continuously

When new work appears, a dependency clears, an important result returns or the lead is about to wait, check for ready unassigned work. These are brief execution decisions, not a requirement to replan after every tool call, fill forms, score expected gains or request separate approval. Adjust delegation to ready work, shared resources and integration capacity.

Continue independent work while agents run. The lead may implement independent critical work, but must still dispatch ready work and process returned results. Wait only when the next step genuinely depends on the awaited result and no other useful work can advance. Start successors from usable returned results without waiting for unrelated branches to finish. Answer only consequential missing context. Existing authorization covers its stated finite chain; do not stop at every subtask, handoff or recoverable failure to request the same permission.

If investigations duplicate effort, multiple workers await the same decision, shared writes conflict or results accumulate faster than they can be integrated, pause the affected expansion and resolve the bottleneck; keep unrelated independent work moving. Purposeful alternative exploration is useful when a key uncertainty warrants comparison, routes can be isolated and selection and stopping criteria are clear. Do not duplicate ordinary investigation just to increase agent count.

The handoff identifies the target/version, environment, covered claims, commands/results, actual output paths and gaps in the existing reply or tracker. Inspect key changes and raw evidence, then reuse covered results; do not treat integration as a reason to rerun the worker's audit. A changed dependency, conflict, unverifiable result or missing coverage triggers only the affected checks. DONE means inspect and integrate; DONE_WITH_CONCERNS means assess material concerns; NEEDS_CONTEXT means supply missing decisive input; BLOCKED means change approach or report the actual dependency. Never retry an unchanged failure mechanically.

## Review and integrate

Check requirements and quality together at a useful delivery boundary. A focused self-review is sufficient for routine work. Use spec-reviewer-prompt.md or code-quality-reviewer-prompt.md when independent review is required or adds material confidence; two separate reviewer agents and serial approval rounds are not the default.

Fix actual blockers and recheck affected parts. Advisory improvements stay nonblocking and out of scope. Required independent review, CI, security and release gates still apply. A review finding does not automatically reopen the entire plan or stop unrelated authorized work.

Run the smallest relevant user-visible acceptance plus mandatory checks. Reuse still-valid results for unchanged state; reserve full/shared-environment checks for their real trigger and run one instance per shared resource. Inspect final artifact state or git diff/status before reporting.

## Boundaries and fallback

A success report alone is not proof. Do not exceed authorization for commits, pushes, messages, publication, deletion or live changes. Keep production, paid calls, credentials, destructive actions and native approvals within their actual boundaries.

Complete a single immediate operation or a short task inline when handoff would repeat most of the work; that reason applies only to that item, not to other ready work. If delegation is unavailable, execute inline with the same acceptance and review responsibilities. Do not create substitute processes solely to mimic agent roles.
