# 工具范围控制

按当前任务的需要选择工具，把上下文花在有效操作与证据上。

## 任务内周期自检

在工具密集任务开始时使用本 skill，之后在执行中主动复查，无需用户重复提示。默认节奏：

- 开始任务时确定本阶段需要的工具范围。
- 距上次自检约有 100 次工具调用时，做一次简短复查。
- 阶段切换、工具调用失败或反复检索同一入口时，提前复查并重新起算。

次数在当前上下文中近似追踪即可；批量调用按其中实际调用的工具估算。上下文压缩或接续后无法判断时，先复查再重新起算。保留上次确定的工具范围，避免反复加载本文件或重读完整目录。

复查只回答三个问题：本阶段还需要哪些能力？已有入口能否直接复用？是否有新缺口或重复获取的上下文？直接使用当前证据，无变化时继续任务；只有需要核实缺口时才补充工具调用。不要为自检再跑扫描、整套测试或额外模型调用。

这是一条由执行中的 agent 遵循的自检约定，不是精确计数器。空闲时不运行，不创建定时任务、后台进程或持久计数文件。只有范围发生实质变化或需要用户处理时才简短说明；自检不自动修改配置或关闭工具。

## 当前任务中的工具选择

1. 明确本阶段要得到什么结果，以及所需的验证、确认和恢复入口；据此选择必要能力。
2. 先复用本会话已发现、适合该操作的工具；有缺口时才按名称或说明搜索，并读取相关用法。只读取当前需要的 skill 和参考材料，避免为挑选入口而展开整个目录或所有工具定义。
3. 工具名称、用法和连接检查结果仍适用于当前操作时直接复用；发生接口变化、连接失败或任务阶段变化时，再补充发现与核查。
4. 用户指定了服务或工具时遵循其选择。任务缺少能力就扩大范围，保留完成任务所必需的检查和操作入口。
5. 用户需要持久关闭工具或调整 skill 选集时，结合明确目标、配置和使用证据提出最小可逆变更，列出影响及恢复方式，按原有授权和部署流程执行。本轮没用过某个工具，不足以证明以后不需要它。

纯 skill 能指导按需发现和使用，但不能从运行时卸载已加载的工具定义。报告时区分“本次选择了哪些工具”和“实际关闭了哪些能力”；只有后者经配置及运行时核实后，才能声称已裁剪。未测量时不报告 token 节省比例。
