# 工具范围控制

按当前任务的需要选择工具，把上下文花在有效操作与证据上。

## 周期巡检

用宿主原生定时任务调用本 skill，周期由用户选择；建议每周一次。skill 本身不提供时钟或后台进程。设置或调整周期时复用已有任务，并回读确认启用状态和下次运行时间。

每次定时触发时：

1. 先读目标项目规则，只读核对环境的 skill 选集、受管清单及已有部署状态；在本仓库运行 `pwsh -NoProfile -File scripts/agent-dotfiles.ps1 env list`，结合 `harness-source/envs/` 与 `manifests/managed-skills.*.txt` 检查缺项、重复或平台不兼容的选择。部署状态只代表上次记录，不等同于 live 内容。
2. 需要判断配置漂移时复用项目已有只读状态命令；需要判断工具是否闲置时只用已授权的使用证据。缺少使用统计就注明证据不足，不扫描历史会话正文，也不把本轮未调用视为可删除依据。
3. 对发现给出最小可逆建议，写清依据、影响和恢复方式；与本聊天上次已报告结果对照，避免反复报告同一建议。定时巡检不执行 Apply、关闭工具或修改配置。
4. 没有新问题或可执行建议时保持安静；有新发现、检查失败或需要用户处理时才通知，并简述范围与下一步。

调度器可直接读取仓库中的本文件，使后续修改按源文件生效。任务 ID、机器路径和运行记录留在宿主本机，不写入可共享的 skill；本机路径失效时报告阻塞。

## 当前任务中的工具选择

1. 明确本阶段要得到什么结果，以及所需的验证、确认和恢复入口；据此选择必要能力。
2. 先复用本会话已发现、适合该操作的工具；有缺口时才按名称或说明搜索，并读取相关用法。只读取当前需要的 skill 和参考材料，避免为挑选入口而展开整个目录或所有工具定义。
3. 工具名称、用法和连接检查结果仍适用于当前操作时直接复用；发生接口变化、连接失败或任务阶段变化时，再补充发现与核查。
4. 用户指定了服务或工具时遵循其选择。任务缺少能力就扩大范围，保留完成任务所必需的检查和操作入口。
5. 用户需要持久关闭工具或调整 skill 选集时，结合明确目标、配置和使用证据提出最小可逆变更，列出影响及恢复方式，按原有授权和部署流程执行。本轮没用过某个工具，不足以证明以后不需要它。

纯 skill 能指导按需发现和使用，但不能从运行时卸载已加载的工具定义。报告时区分“本次选择了哪些工具”和“实际关闭了哪些能力”；只有后者经配置及运行时核实后，才能声称已裁剪。未测量时不报告 token 节省比例。
