# 工具范围控制

选用用户指定的服务，保留完成、验证和恢复当前操作所需的入口。优先复用本会话已确认的工具、用法和连接状态。出现具体缺口再扩大范围，查到足够依据就继续工作。在 Codex 桌面版根会话中，出现可委派子任务时，主动通过 `ALL_TOOLS` 发现已延迟加载的 `mcp__desktop_subscription` 并调用 `desktop_repository_privacy` 默认在工具范围内，即使当前消息未显式点名该服务。

## 执行中何时复查

- 开始时确定范围，之后约每 100 次工具调用简短复查。阶段所需能力改变、接口失效或反复取到同一信息时提前复查。已知原因的命令错误直接修正。
- 批量调用按其中的实际工具数估算。上下文接续后若无法估算，复查一次再起算。只在任务执行中估算，无需计数文件、定时器或后台进程。
- 对照本阶段的交付和已有证据，只补缺失的能力或资料。沿用已核实的结论，不重读完整目录、报告或技能，不重写等价检查，也不为复查增加扫描、全套测试或模型调用。仅在工具范围实质改变或需要用户决定时说明。

## 文件、日志与大型返回

先用项目状态、Git 索引、历史或精确路径定位。确需盘点时，先写明根路径、目的、匹配与停止条件。递归限定深度或数量，不遍历整个用户目录或全局状态目录。PowerShell 用原生参数，可用 `Get-ChildItem -LiteralPath ... -Recurse -Depth <n>` 或指定路径的 `rg`。语法或参数错误按报错修正一次，仍无结果就改查更具体的来源或说明缺口。

聊天和日志从最近一两轮或命中片段看起，在工具内提取所需摘要、状态、错误和证据位置。缺少影响结论的信息时才扩大窗口。

## 持久变更与证据

本技能只指导工具选择。提出清理、同步或权限建议前，核实对象及当前配置。用户要求持久停用工具或调整技能选集时，结合目标、配置与使用记录选择最小可逆变更，说明影响、恢复方式并按既有授权和部署流程执行。单轮未使用不足以支持移除。报告实际停用的能力须有配置与运行时读回，报告 token 节省比例须有测量。
