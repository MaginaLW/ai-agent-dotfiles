# 真实反馈的记账入口

收到可归属的实际评分且需要落盘时读取。本说明及脚本不授予写入许可。

## 调用与结果

先核实当前任务允许写入的私有台账精确位置。沿用已有台账；建议为
`%LOCALAPPDATA%/ai-agent-dotfiles.feedback/approval-feedback.md`，不自动创建空台账。
调用前分别确认：用户许可覆盖这次台账写入，当前工具权限覆盖台账、相邻 `.lock` 和同目录临时替换文件。
复用当前权限说明及仍有效的已有证据，不为每条反馈探测文件系统；可读、路径存在或业务动作获批均不能替代写入条件。
默认工作区写权限通常不包含全局台账目录。顺带记账的任一条件缺失或无法确认时，保留原始输入／来源并标明待归并，
不调用 recorder 或开写句柄试权限，不换位置、不自动提权，也不为记账另发确认。条件恢复后先重核两者，再正常归并。
本次任务若已明确要求并授权写入该精确全局台账，复用这项许可，通过平台正式入口取得仅覆盖台账、锁和临时替换所需的权限，
不重复询问已有许可；原生权限获准前不执行 recorder，拒绝后停止写入并保留待归并。评分或业务批准不触发此路径，仍不改 ACL、换位置或绕过拒绝。
输入 JSON 放在当前任务已预检且被忽略的临时目录，不进 Git、不放 live Skill 目录；
记录后只清理本任务不再需要的输入文件。脚本不下载依赖、不扫描聊天、不访问账户或模型。

输入包含且仅包含下列八个字段；示例值均为占位，不能作为真实证据：

```json
{
  "Task": "independent-task-reference",
  "Request": "A01",
  "Project": "project-short-name",
  "Client": "Codex",
  "Scope": "reviewed skill update in the existing environment",
  "Score": 1,
  "Permission": "Approved",
  "Source": "original-chat-reference/tool-call-id/question-0/answer"
}
```

`Task` 是独立任务的稳定引用，同任务重试和跨聊天继续沿用；不能以每轮编号代替。
`Source` 唯一定位实际提交的答复，包含原聊天、调用及问题索引；来源不清不猜、不计门槛。
`Permission` 只能是 `Approved`、`Denied`、`Unspecified`，描述该回复是否表达许可，
不表示许可目前有效。仅评分用 `Unspecified`，否定加低分仍用 `Denied`。
`Score` 只接受实际整数 0–3，不评分就不调用脚本。
其他字段为非空单行短文本；不要放完整会话、配置、凭据、机器名或私有路径。

在 Skill 实际安装位置调用随包脚本，将两个参数解析成已核实的绝对路径：

```powershell
pwsh -NoProfile -File <skill-root>/scripts/record-feedback.ps1 -EntryPath <private-input.json> -LedgerPath <private-ledger.md>
```

脚本向标准输出返回一条 JSON，退出码 0 为 `Recorded` 或 `Duplicate`，并已读回核实；
退出码 1 为 `Pending`，携带简短原因，不输出输入或异常原文。无法启动脚本也属于待归并。
`Pending.Stage` 只标明失败边界：`ValidateInput`、`ValidateStoragePath`、`PrepareStorage`、
`AcquireLock`、`ReadLedger`、`WriteTemporary`、`PublishLedger`、`ReadBack` 或 `Cleanup`。
例如 `StorageFailure / AcquireLock` 只证明锁操作失败；路径被目录占用和访问被拒都可能发生在此，
不能据此推定 ACL、沙盒或代码缺陷。旧回执没有阶段时保留未知，不为补诊断重跑真实写入。
检查退出码及状态，不能把执行过命令当作已保存。写入结果未知时先读回来源标记再重放同一输入，
不要换来源制造新记录；内容不同的同来源提交返回 `Conflict`，保留原始记录后核实真实答复。
待归并时保留原始输入和 `Source`，不要清理仍需重放的文件；正常访问条件恢复且已有写入授权仍有效时，
在正常归并机会重放同一条目。访问拒绝不触发自动提权、改 ACL、换台账或换工具。

## 存储与协作边界

脚本以客户端、稳定任务引用和原答复来源生成标识；完全相同的提交只保存一次。
同任务不同答复分别保存，仍只能支持一个独立任务样本；2／3 分及否定反例不可被低分覆盖。
脚本不评价任务独立性、不合并类别、不计算三任务门槛、不提出或启用授权。

既有 Markdown 内容按原字节保留，新反馈以带来源标识的 JSON 块追加。
旧人工条目不自动迁移或转换；回补前先对照原始来源和旧条目，已存在就沿用，避免双记。
计数、反例及提案状态使用同台账的人工任务说明，保留来源；不要修改脚本写入的反馈块。

同目录 `.lock` 文件通过操作系统独占句柄串行化写入；文件存在本身不代表正在占用，
不要删除锁文件解锁。并发占用立即返回 `Pending/Busy`，不后台重试、不绕过入口手改。
在后续正常归并机会检查原状态再重放即可，不因此阻塞当前授权工作。
人工维护任务说明也必须等记录进程结束，并由一个明确记录者完成；不能与脚本并发写。
没有安全串行维护条件时保留待更新摘要，不能直接改台账。

脚本使用同目录临时文件、刷新、原子替换及读回；正常退出会清理本次未采用的临时文件。
中断可能留下本次 `.tmp`，只在确认没有运行中记录者且文件归属可核实时清理；不能拿残留文件当成功。
输入限 64 KiB，既有台账限 4 MiB，拒绝链接路径；超限或存储拒绝保留为待归并，
不自动换位置、改 ACL、提权、轮转或删除原记录。

Skill 不持续运行。跨聊天归并依赖可用的来源读取工具、台账写入许可及实际执行者；
无入口就明确覆盖范围。收尾时只汇报必要的待归并缺口，避免每条评分增加一条通知。
