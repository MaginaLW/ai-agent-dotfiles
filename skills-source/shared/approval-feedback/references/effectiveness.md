# 审批流程修改后的效果核验

仅在实际审批流程修订任务、用户要求核验或自然可比决策出现时按需读取；普通开发、无关阶段和一般工具检查不触发此流程。目的为核实具体修改是否消除了原来的打断；本说明不授予执行、读取其他聊天或写入台账的权限。

## 先留可比较的基线

沿用原提案或任务说明，补齐以下最小信息，不另建监控系统：

- **范围与版本：** 项目／客户端、动作与对象、预算／目的地、次数与剩余额度、旧规则或原问题的精确来源、新的有效授权或修订来源，以及实际部署／加载状态。台账里的“已批准”本身不能作为执行依据。
- **预期变化：** 写清旧条款必需询问、而新有效约定允许继续的具体条件及保留例外。纠正误读时引用原来那次多余询问；旧规则本就允许继续、只有低分或安装记录，均不足以推算省了几次。
- **观察边界：** 当前任务有后续动作就观察到本次正常收尾，否则在下一个实际相关任务收尾核对。固定该任务的开始／结束来源与可访问范围；用户另有期限时沿用。不要为取样启动工作、制造恢复、等待未来任务或添加定时器；没有自动跨聊天收集能力就如实注明。

已存在的修改可以按可核实的旧／新来源补基线，但历史区间不完整时不能补造当时的效果。没有可靠基线仍可记录实际发生的询问，不能给出“少问了 N 次”的结论。

## 记录真实决策机会

只记录实际遇到、与预期变化相关的用户决策点，不给每次工具调用加日志。决定是否需要询问前核实当前有效权限；动作完成后读回结果，在原任务收尾合并记录：

| 分类 | 所需证据与处理 |
|---|---|
| 已免除 S | 旧条款／原问题与这次动作可比；新有效许可覆盖；相关完整交互区间可核实没有该确认，且动作实际完成并读回。仅有“继续执行”的自述或单条工具成功不够 |
| 仍重复 Q | 同样可比且已有有效许可，仍发出了原本要消除的确认；保留实际问题来源并定位原因，不靠低分跳过当前门禁 |
| 证据不足 U | 有真实相关决策，但基线、实际加载、交互区间或动作结果不足以判定。保留已知来源和缺口，不当成功，也不当零询问 |
| 必要／范围外 H | 新预算／目的地／对象、已撤销许可、规则保留例外或平台硬确认。按有效要求处理，单列而不算优化失败或省下的确认 |

每个机会用稳定任务引用及实际动作／原始交互来源定位。同一决策的重放、跨聊天继续和重复采集去重；不同阶段确有不同决策可分别观察，但不能据此增加独立评分任务数。一个机会即使重复问多次，在 Q 中仍只计一处，可另附实际问题来源。

S 必须同时有完整相关交互和完成证据；缺失的聊天、未读取的回合及任务外静默不能证明没有问。源已改但尚未部署／加载时标“待生效”，不据此使用新许可，也不计 S。对其他客户端只报告实际看过的范围。

## 在原台账留一段任务说明

沿用台账的建议跟踪字段；效果观察不是用户评分，不传给只接受真实分数的 `record-feedback.ps1`，不改原反馈块。仅在已有写入授权且满足 [recording.md 的人工串行维护条件](recording.md#存储与协作边界)时由一个记录者保存并读回；否则在当前任务保留待归并摘要及原因，不为记账另问或阻塞交付。

可直接使用下列短模板，保留最小来源，不存完整聊天、凭据或私有路径：

```text
关联：原提案／任务引用；项目、客户端和实际观察版本。
基线与许可：旧条款或原问题来源；新有效来源；生效核实点。
预期：要消除的具体确认条件；仍保留的例外。
窗口：本次真实相关任务的开始／结束来源；实际可见范围。
机会：任务＋动作来源；S／Q／U／H；相关交互区间与结果证据。
汇总：可比机会 O=S+Q+U；S、Q、U；另列 H；去重依据。
结论与后续：本范围已观察／仍重复／待生效／无触发机会／证据不足；原因与下一正常检查点。
```

没有真实相关决策时记“无触发机会”，不以 O=0 宣称改善。O 与各项均限已读取窗口；U 不从分母删除以提高成功率。不混合不同项目、条款或客户端，不用总审批量下降作因果证明。只有 S 的证据完整，才能说“该范围观察到 S 处原确认被免除”，并同时给出 Q、U 及覆盖边界；这不是全局前后节省量，也不估算节省时间。

收尾可单独确认“真实反馈已推动具体提案、批准及条款落地”，但这不是 S；只有旧正文实际加载的证据时，不将结果归因于最新修订。无后续可比机会就按已读取窗口正常收尾，说明下一自然核验点，不靠等待未来任务、持续扩查或反复报告“待观察”延长当前交付。

Q 出现时区分旧正文未刷新、有效许可被误读、源条款未实际修改或范围分错；纠正当前已获准的执行误读，规则问题准备精确修订，需要部署则走原预演／授权流程，不循环只报“待观察”。U 列明具体缺口，下一次自然机会再核对。

H 保留当前必要确认；真实 0／1 分若指向已知、可修改且将再次打断的逐轮条款，在收到反馈的当前响应中按[旧规则修订](workflows.md#旧规则修订)准备精确源差异，不以“必要确认”或等待下一次机会代替处置。提案尚未生效时不扩大许可，也不把 H 改计为 Q。H 中的必要确认若漏掉，立即停止受影响的后续动作并核实状态和权限，不能记为 S；所需补救另按实际授权执行。
