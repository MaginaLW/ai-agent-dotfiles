# 审批反馈

减少没有决策价值的打断，让必要选择、执行许可和反馈各自清楚。全局可发现不等于全局授权；每个项目、客户端和动作分别核实范围。

普通开发只做当前动作的最小授权判断；已有有效许可就直接推进。没有真实评分或具体重复审批，不读全台账、不启动效果审计；本技能不使其他技能、计划或每个阶段成为审批入口。

## 发问前的最小检查

先复用已有授权；相关低分或重复阻塞反馈按[收到反馈与再次询问](#收到反馈与再次询问)在当前响应中处理，不能只重新展示评分入口。确需新的执行确认或方案选择时，核对[当前交互段](#同一次确认完成许可与可选评分)：同一题带会话短编号、可省略的评分入口及分数含义，不能只写“可选评 0–3 分”。选项足够时合并许可和评分；受限界面保留原选择，附当前交互段的一行回复模板。

发现 Skill 更新、上下文恢复后无法核实所读版本，或仍沿用旧“一行可选反馈”时，重新读取当前交互段。曾读过 Skill、声称已启用或全局路由已刷新，都不能代替当前正文和实际发问检查；已核实且未变的版本不为每次工具调用重读。已经发出的待答请求不为升级重发，已有许可不重问；下一次新询问使用当前格式。

在 Codex 长会话中，发出新的执行确认或方案选择前，先看将发送的文本：若没有会话短编号，或仍用旧“一行可选反馈”、无法说明当前评分含义（原生硬审批无法展示时除外），按当前正文未核实处理，先重读本节和[同一次确认完成许可与可选评分](#同一次确认完成许可与可选评分)，再决定是否发问。已有授权覆盖当前动作时直接继续，不因这项检查另发确认；已经发出、仍在等待答复的问题不重发。

纯事实澄清不附评分。原生硬审批保留按钮，按当前交互段关联可展示的编号与补评入口，不换成评分 Ask。验收分别核实目录发现、当前正文读取、适用询问的实际输出和真实反馈归并；前一项不代替后一项，无触发机会或证据不足如实标注。

## 询问前先判断

1. **分清对象。** 核对确认、CI、Gate 与独审的真实来源和适用条件；用户明确要求、平台强制和既有且适用的项目门禁照常满足。代理在当前任务或计划中自行增加的评议不自动成为阻塞门禁，可按风险合并、自审或取消。无人工问答就不是评分样本；平台硬确认走正式入口，不自动点击、不换工具或身份绕过。
2. **找到有效依据。** 只定位当前动作相关的用户指令、全局／项目／子目录规则、已调用 Skill 和平台要求。按实际指令优先级、适用范围及覆盖关系判断，不一律取更严，也不默认项目、新文件或本 Skill 总是优先。设计提议、历史状态、台账“已确认”和工具可调用均不授予权限。
3. **比较实际变化。** 用一行界定：项目／环境与客户端 + 对象和动作 + 数据与目的地 + 预算上限 + 例外。原始预算与授权须可核实；新目的地、数据、权限、费用或外部副作用不继承旧结论。混合动作分清范围，可在一次请求中列出选择。
4. **已有许可就继续。** 当前任务已明确授权、范围无实质变化且平台允许时，直接完成后续已授权阶段；不为评分、记账或修改规则再问。逐次许可要求若已被当次明确授权满足，不必先修改规则文件。
5. **只问真正缺少的决定。** 能明确消解的误读或优先关系直接处理。真实不可判定冲突只暂停受影响动作，列实际文件条款、授权缺口和最小选择，集中问一次；继续独立已授权工作。同一任务、范围、有效条款和决定未变时不重复问。

反复打断来自旧规则时，主动准备源文件的最小修订提案，不停在“有冲突”；按 [workflows.md 的旧规则修订](references/workflows.md#旧规则修订)推进。该引用仅在实际准备规则修改时读取。

## 收到反馈与再次询问

收到真实 0／1 分，或用户指出“多次评分仍阻塞／纠错未落实”时，在当前响应中先处理具体问题，再按条件记账。不等下一次询问、第二次评分或三个独立任务；不以“已记录、建议以后修改、继续观察”代替处置。用户概述不是新的精确分数，不据此补造历史评分。

只定位一处相关的实际询问、当时已有许可和造成停顿的有效来源；当前聊天足够就不扩查，需查历史时沿相关台账来源取最小窗口。查不到原询问或源条款就说明缺口，不凭低分断定所有确认多余，也不为评分归属追问用户。

- **执行误读：** 已有许可覆盖且范围未变时，取消多余确认并实际完成受影响的已授权工作，读回结果；进度通知后继续，不再问是否继续。已经完成的动作不为证明纠错而重跑。
- **有效规则造成重复：** 按[旧规则修订](references/workflows.md#旧规则修订)准备精确源差异。修改已在当前授权内就落实并验证；缺规则写入或部署许可时，先完成可审阅差异和必要检查，再集中提出真正缺少的决定。不能只列改进方向，也不能从低分推导新权限。
- **平台限制或证据不足：** 指出具体限制或缺失来源及影响的动作，继续独立已授权工作。已拒绝／暂缓的同一提案不重复推销；无可修改入口时不承诺已经修复。

在原任务正常汇报中简述问题来源、实际纠正动作及结果证据，或精确未完成项和原因；无需另建审计、评分题或通知。记账成功不等于纠错，源已改不等于部署，部署不等于行为改善。

有可归属的实际评分时，再用独立任务引用、客户端和含具体问题索引的原始答复来源关联。先核实台账写入许可及当前工具可写范围（含锁和临时替换）；评分、业务批准、可读均不代替写入条件。条件不足不调用 recorder 试权限，保留来源并标“待归并”，不阻塞上述纠错、不为记账加确认。条件具备后按[记账说明](references/recording.md)执行，只有 `Recorded` 或 `Duplicate` 算保存。

再次准备同类询问时，复用相关处置结果，只说明相对已有授权真正新增的决定。当前聊天与可核实的历史反馈都可支持纠错，不以属于另一任务为由忽略。同任务多次低分不增加独立样本数；三个独立任务的门槛只用于跨任务持续授权建议，不限制纠正误读或准备源条款修订。

## 同一次确认完成许可与可选评分

仅给真正需要用户回复的确认分配本会话短编号，如 `A01`，并绑定当前任务、客户端、明确动作与范围。后续补评分沿用该号；新确认用新号，同任务多号仍只算一个独立任务。编号不是权限，全局不唯一，跨会话须有任务及原始来源，不凭同号合并。

能用当前允许的选择型 Ask、且选项数足够时，把许可和评分放在同一题，让用户一次选择完成。明确说明 **0–3 只评价这次询问，不授予以后权限**；二选一执行确认可用：

- 本次批准，不评分
- 本次批准｜0：不用问，也不单独通知
- 本次批准｜1：不用问，结果告诉我
- 本次批准｜2：需要我作选择
- 本次批准｜3：这类应逐次确认
- 本次不批准，不评分

不把低分设为默认／推荐，不把未提交的预选当回复。不强求每种 Ask 都有六项；选项不足、原题是方案选择或界面不支持时，保留原选择，只附一行带编号和含义的文字模板：`A01：可回复「批准」或「批准；1分」；方案题可写「选A；2分」。0不用问不单报／1结果告知／2需要选择／3逐次确认；评分可省略。` 不扩成所有方案与分数的组合，不另开评分题或追问，不给普通进度、工具调用或检查附评分。选方案只表达原题的选择，不自动许可后续部署、发送或合并。

原生批准弹窗保留原按钮，不承诺添加评分按钮或用另一种 Ask 替代硬确认。能在理由或相关说明展示时，将编号与具体动作对应一次，并给补评格式 `A01=1`；点批准只算许可，不自动算分。不要以“刚才那次”作为默认指引。确实无法显示编号时只提供一次可选反馈说明；用户引用不清或多次弹窗无法区分时，保留为未关联反馈，不猜归属、不计阈值，也不为评分补问或阻塞合法工作。

短请求示例（实际使用须核实并说明真实目标、变化及预算；例句不授予权限）：

> A01｜拟对刚说明的目标重试同一调用。已读回确认前次未生效，只修正启动前路径，预算和外部副作用不变。本次是否批准？可回复「批准」或「批准；1分」；评分可省略。0不用问不单报／1结果告知／2需要选择／3逐次确认。

| 分数 | 用户含义 | 如何处理 |
|---|---|---|
| 0 | 不用问，也无需单独通知 | 同类打断的反馈；异常、阻塞和必要结果仍报告 |
| 1 | 不用问，结果告诉我即可 | 同类打断的反馈；结果并入原任务汇报 |
| 2 | 需要我作选择 | 检查缺少的选择或混类；不被低分平均掉 |
| 3 | 本类应保留逐次确认 | 暂停该范围免重复确认建议或约定的依赖，核实有效来源 |

评分是打断价值，不是风险、方案质量或执行许可。分别解释同一回复中的许可与评分：

- “同意，1 分”：在请求所说明的范围内继续，另记实际反馈。
- 选择“本次批准｜某分数”或回复“批准；某分数”：分别解析许可和评分；明确批准加 2／3 分不撤销本次许可，也不因分数再问一次，后续免确认建议仍受反例约束。
- `A01=1`：仅给对应请求补评分；不授予新许可，不重复已经执行的动作。保留“同意／1分”等旧回复的兼容性，只有来源唯一可核实时才关联；不明确的许可须澄清执行范围，单纯评分不明则不追问。
- “1 分”：只记反馈；动作缺许可时仍等待许可。
- “同意”：按范围继续，不计分也不追问。
- 未回复：不推定同意或分数，其他独立已授权工作继续。
- “不做，0 分”：不执行，保留反馈；该样本不支持免重复确认建议。
- “以后这类别问”等明确指令：单独核实范围和效力，不从分数推断。只澄清影响执行的真实歧义。

## 记录、去重与建议

有真实反馈需要归并时才使用私有单文件台账；建议位置为 `%LOCALAPPDATA%/ai-agent-dotfiles.feedback/approval-feedback.md`，实际先核实本机可写性和写入授权。不要仅为加载 Skill 创建空台账。不进 Git、Skill 目录、生成物、部署状态或 config-sync；不存凭据、机器标识及完整会话。

台账只保留五组信息；随包脚本独占锁保护单次写入，所有记录者都走同一入口。其他会话仅在具有对应访问和写入许可时提交最小摘要；没有共同入口就标明尚未跨聊天归并，不承诺自动收集：

| 字段组 | 内容 |
|---|---|
| 关联 | 请求短编号、独立任务引用、项目与客户端短名 |
| 范围 | 类别一行、相对已有授权的变化；必要时附决策类型 |
| 用户输入 | 实际评分或未评分、本次许可／否定、最小来源引用 |
| 计数 | 独立性、去重或排除原因、反例；不能证明独立就不计阈值 |
| 建议跟踪 | 收集／待建议／已提出／暂缓／暂停及原始授权或修订来源、最后核实点 |

脚本只保存不可变的反馈事实，来源身份相同的原样重放去重，内容冲突保留为待核实；计数与建议跟踪由 agent 复核并另记在同一台账的相应任务说明中，不能覆盖原始记录。脚本不判断许可效力或自动计算门槛。

样本单位为独立任务中的一次用户判断。同任务的重试、拆步骤、跨会话继续只计一份；保留该任务的各次原始反馈，同任务后续 2／3 分或否定执行优先阻止其支持建议。台账写入失败不阻塞已获准工作；未可靠保存的反馈不计跨任务门槛，但当前可核实的反馈仍用于纠正重复询问，不为补记发确认。

同一明确范围的 **三个独立任务均有真实 0–1 分、本次许可无冲突，且期间无 2–3 分或未解决反例／规则冲突**，才提出一次窄范围后续授权建议。不要平均分、补造历史分、把重试拆成样本或挑掉高分；遗漏的真实评分只能对照原答复补记并去重。反例先查是否混类；收窄须保留原证据，按新范围重新积累。暂缓／拒绝后不反复建议，除非用户重提或范围实质改变。

建议列实际项目／环境、客户端、动作／对象、数据／目的地、预算、例外、通知、期限或结束条件、撤销方式和授权保存位置。达标仅产生建议，不开始执行未来动作。用户直接明确授权不必先采满三份评分；持久化规则必须另有对应写入许可，正式入口写成并读回后才能依赖。

## 修订后的实际效果

仅在当前任务实际修改审批流程、用户要求核验，或自然出现与已改条款直接可比的决策时核验效果；普通开发收尾不重启审计。获准纠错／规则修订落地后，复用原任务中的最小基线与证据，在相关机会及正常收尾核验，不以新评分或新审批请求为前提。按[效果核验](references/effectiveness.md)留下旧条款／原问题基线、预期消除的确认和下一个正常收尾检查点；后续用同范围真实决策逐项核对。没有机会不制造请求、不等待采样；不把效果记录当新许可。

效果分别核实：反馈是否保存、具体提案是否提出、获准规则是否部署／加载、后续实际询问是否减少。安装成功和脚本测试不证明行为改变；无机会、待生效、证据不足分别报告，未减少则定位原因，不追加评分问卷。必要确认、异常和结果报告仍保留。

效果证据按客户端分别记录。当前主要使用的客户端有真实机会时先核验；未实际使用的客户端保持未验证，不用其缺失阻塞当前客户端的改进，也不能把结果外推到其他客户端。

## 连续交付与偏好

同一协议可用于阶段衔接、有限失败恢复、等价方案、工具与并行安排、检查后的处置、预算内资源及通知。既有授权覆盖的实现、检查和直接相关修复连续推进；无关问题记录后续，不扩大交付，不减少必需门禁。确认提案前核实必要权限、依赖和窗口余量；仅在确认无副作用、原授权未禁止且范围与累计预算不变时，修正权限或工具准备失败后复用原许可。不得自行添加笼统失败即重批的条件；既有明确失败停止、未知结果及原生审批仍遵守。

仅为确需时限的未来提案约定一次激活事件、相对持续时长、最晚激活时刻或条件（含时区）及停止条件，避免等待答复消耗执行窗口；不为普通任务新增时间审批。按已获批约定一次激活，同一授权链的执行者共用该窗口；等待、恢复、工具或会话切换均不重新计时、不重置已消耗预算。提案前按计划次数、必要修复和必需复核估算窗口及启动余量，在已有许可允许时先完成不消耗受限资源的准备。已有固定截止到期时，不把迟到的“批准”推定为延期，也不回填相对窗口；只暂停受影响动作并集中补足缺少的时间决定，不重问其他仍有效许可。

已明确的“优先复用、最小改动”等偏好按适用范围使用；低分或一次成功不证明技术偏好。可提出偏好修订建议，跨任务保存前给精确差异并取得相应授权。验收、返工、费用和用户纠正是客观结果，未知就留未知，不换算成用户评分，不增加阶段问卷。

恢复先确认是否已生效；结果未知先读回，不盲目重试。仅在原许可、预算、副作用和允许重试次数内恢复。付费调用须有涵盖实际调用、累计总额、单次上限、轮次和停止条件的明确许可；不可靠的预算不支持继续付费。正常 503／执行故障不算安全拒绝或审批反例。

## Git 与长期规则

提交、普通推送、合并分别核实许可；不因低分自动执行。已有规则允许的提交／推送照常完成，不以本 Skill 或台账为新门槛。准备执行这些动作时按 [workflows.md 的 Git 链](references/workflows.md#git-链)核实实际目标、最新检查、审查及读回；无需读取无关案例。

旧规则长期修订可以在发现根因后立即提出，无需等三份评分。获准后只改真正源文件和精确条款，保留个人覆盖与其他 WIP；生成物、live 根及全局配置走其现有构建／部署流程。项目内授权不扩展到全局。系统／开发者限制或平台硬确认没有可由本 Skill 修改的入口时，准确说明限制。

## 生效、撤销与失败

每个下一动作核实当前有效来源、范围和撤销状态；复用仍有效的相关证据，不全量重读无关文件。无可核实来源就不依赖自动处理；台账与缓存不续权，也不默认跨项目／平台／客户端迁移。

用户要求“以后问我”、出现 2／3 分反例或范围不符时，立即暂停后续动作依赖该范围约定并核实来源。0／1 分不会自行恢复权限。跨会话没有共同可读的当前正式来源时，不承诺同步生效或瞬时撤销；只适用于能核实约定的会话。

恢复依赖前须能核实反例的处理结论和当前明确授权；原许可已撤销时须有新的有效许可。不能凭后续低分、台账状态或 agent 自认问题解决恢复。

规则写入结果未知先读回；失败保持原有效边界。Skill 未加载时回到原有指令，不假装已启用，也不新增审批层。已开始／完成的动作先核实真实状态，补救另依权限，不承诺撤销规则能收回已发送数据或费用。必要结果和异常报告始终保留。
