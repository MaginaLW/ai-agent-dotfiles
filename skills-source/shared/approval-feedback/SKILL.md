# 审批反馈

减少没有决策价值的打断，让**直接执行**成为常规开发的默认路径。全局可发现不等于全局授权；每个项目、客户端和动作分别核实范围。

## 默认直接执行（不要多问）

- **工作区内常规开发直接推进：** 已授权任务范围内的读取、编辑、构建、局部测试、状态查询及可恢复准备连续完成，不发文字确认、不拆阶段重问、不因换工具或修正明确命令错误再问。
- **不新增中间审批：** 本 Skill、计划步骤、自查或常规工具调用都不应变成新的确认入口；纯事实澄清不附带评分模板。
- **减少触发原生弹窗（尤其 Windows PowerShell）：**
  - 优先执行**单条、短小、参数带引号、且工作区内的命令**；避免无意义的 `&&` 串接、复杂管道或 PowerShell 下未加引号的逗号参数（如 `--json a,b,c`），以免破坏 Codex `prefix_rule` 前缀匹配导致重复弹窗。
  - 临时文件留在当前工作区允许目录或已配置的 `writable_roots` 内，避免顺手写入主目录或系统全局目录触发提权审批。

## 何时才发问与发问前检查

仅在以下真正缺少决定的场景停下来问，且能合并就一次问清：

1. **不可逆或高风险动作：** 破坏性删除、生产变更、凭据读取/导出、外部发送（如 `git push`、发 PR/消息）、额外付费调用或工作区外写入（已有有效规则覆盖者除外）。
2. **原生硬审批：** 保留平台原有弹窗按钮，不承诺替原生弹窗增加按钮；若界面支持补充说明，可在说明中标一次会话短编号。
3. **规则冲突或真实歧义：** 已有许可足够时直接推进；真有冲突只暂停受影响动作，列出冲突条款、授权缺口与最小选择，继续其他独立已授权工作。

同一任务范围内、范围与风险未变时不重复问；当前任务已覆盖后续同类阶段时直接复用，不要求先改规则文件再做本次动作。

## 一次确认完成许可与可选评分

仅对真正需要用户决定的**非原生**执行确认或方案选择分配会话短编号（如 `A01`），并写明动作、对象、目的地及预算/停止条件。能使用多选 Ask 时将许可与 `0–3` 评分合并为一题，并明确说明 **0–3 只评价这次打断价值，不授予以后权限**：

- 本次批准，不评分
- 本次批准｜0：不用问，也不单独通知
- 本次批准｜1：不用问，结果告诉我
- 本次批准｜2：需要我作选择
- 本次批准｜3：这类应逐次确认
- 本次不批准，不评分

选项不足、原题为方案选择或界面受限时，保留原选项并附一行模板：`A01：可回复「批准」或「批准；1分」；方案题可写「选A；2分」。0不用问不单报／1结果告知／2需要选择／3逐次确认；评分可省略。`

| 评分 | 含义 | 处理 |
|---|---|---|
| 0 / 1 | 不用问（不单报 / 结果告知） | 同类打断的纠错信号；本次按许可继续，并立即定位减问 |
| 2 | 需要我作选择 | 补充遗漏选项，不与低分平均 |
| 3 | 本类应保留逐次确认 | 暂停依赖该范围免确认约定，核实有效来源 |

- “同意”或选“本次批准，不评分”：按范围继续，不追问分数。
- “1 分”但未写同意：仅作反馈，不得视为本次授权；缺许可时不执行，立即纠错或准备提案。
- `A01=1`：仅补评对应请求，不授予新许可或重跑已执行动作。

## 收到低分或重复阻塞时的双轨处理

收到 `0/1` 分、用户指出“又问重了”，或发现同一动作反复触发打断时，**在当前响应立即处理**（不等多个样本）：

1. **执行误读：** 已有规则或本轮授权已覆盖时，取消多余确认并直接完成受影响工作。
2. **项目规则导致的文字打断：** 按 [workflows.md 的旧规则修订](references/workflows.md#旧规则修订) 定位真实源文件（如 `AGENTS.md`），给出精确 diff、减少的确认、风险与回滚范围，交用户一次审批。同类动作多次扩权时按[权限规则归整](references/workflows.md#权限规则归整)合并同类条款。
3. **原生命令行/沙箱频繁弹窗：** 若阻塞来自 Codex 原生审批而非 `AGENTS.md` 文字规则，直接给出可由用户审阅后加入本机 `~/.codex/rules/default.rules` 的 `prefix_rule(...)` 白名单片段（可附 `codex execpolicy check` 验证命令）或 `[sandbox_workspace_write].writable_roots` 建议，并准确说明本 Skill 不能直接改写本机私有配置。
4. **平台限制或证据不足：** 说明具体限制并继续其他独立已授权工作；未批准或暂缓的提案不反复推销。

仅在需要把真实评分归并到私有台账、涉及有时限窗口提案、或用户要求核验审批修订效果时，才按需读取 [recording.md](references/recording.md)、[workflows.md](references/workflows.md) 或 [effectiveness.md](references/effectiveness.md)；普通开发不加载这些流程，也不为加载 Skill 创建空台账。

## 私有台账与效果边界

- 有真实评分需保存时才使用私有台账（建议位置 `%LOCALAPPDATA%/ai-agent-dotfiles.feedback/approval-feedback.md`），先核实本机可写性与写入授权，并通过随包脚本 `scripts/record-feedback.ps1` 单入口写入；不存凭据、机器标识或完整会话，不入 Git 或 config-sync。
- 统计以独立任务为单位，保留 `2/3` 分与拒绝样本；台账写入失败不阻塞当前纠错、提案或已授权工作，不为补记发确认。
- 提交、普通推送、合并按各自有效许可执行（参见 [workflows.md 的 Git 链](references/workflows.md#git-链)）；规则修订落地与否以实际源文件读回与加载状态为准，出现 `2/3` 分或用户要求“以后问我”时立即停止依赖旧范围约定。
