# 审批反馈

减少没有决策价值的打断，让必要选择、执行许可和反馈各自清楚。全局可发现不等于全局授权；每个项目、客户端和动作分别核实范围。

## 询问前先判断

1. **分清对象。** agent 的确认可以检查是否多余；CI、Gate、独审等质量要求照常满足，无人工问答就不是评分样本；平台硬确认走正式入口，不自动点击、不换工具或身份绕过。
2. **找到有效依据。** 只定位当前动作相关的用户指令、全局／项目／子目录规则、已调用 Skill 和平台要求。按实际指令优先级、适用范围及覆盖关系判断，不一律取更严，也不默认项目、新文件或本 Skill 总是优先。设计提议、历史状态、台账“已确认”和工具可调用均不授予权限。
3. **比较实际变化。** 用一行界定：项目／环境与客户端 + 对象和动作 + 数据与目的地 + 预算上限 + 例外。原始预算与授权须可核实；新目的地、数据、权限、费用或外部副作用不继承旧结论。混合动作分清范围，可在一次请求中列出选择。
4. **已有许可就继续。** 当前任务已明确授权、范围无实质变化且平台允许时，直接完成后续已授权阶段；不为评分、记账或修改规则再问。逐次许可要求若已被当次明确授权满足，不必先修改规则文件。
5. **只问真正缺少的决定。** 能明确消解的误读或优先关系直接处理。真实不可判定冲突只暂停受影响动作，列实际文件条款、授权缺口和最小选择，集中问一次；继续独立已授权工作。同一任务、范围、有效条款和决定未变时不重复问。

反复打断来自旧规则时，主动准备源文件的最小修订提案，不停在“有冲突”；按 [workflows.md 的旧规则修订](references/workflows.md#旧规则修订)推进。该引用仅在实际准备规则修改时读取。

## 一行可选反馈

仅在本来需要用户回复的请求末尾附：**“这次打断有没有决策价值？可选评 0–3 分。”** 不催分，不另开评分对话，不给普通进度、工具调用或检查附评分。平台弹窗不能附文字时，在相关任务说明中只提供一次可选入口，不制造第二轮确认。

短请求示例（实际使用须核实并说明真实目标、变化及预算；例句不授予权限）：

> 拟对刚说明的目标重试同一调用；已读回确认前次未生效，只修正启动前路径，预算和外部副作用不变。本次是否同意？这次打断有没有决策价值？可选评 0–3 分。

| 分数 | 用户含义 | 如何处理 |
|---|---|---|
| 0 | 不用问，也无需单独通知 | 同类打断的反馈；异常、阻塞和必要结果仍报告 |
| 1 | 不用问，结果告诉我即可 | 同类打断的反馈；结果并入原任务汇报 |
| 2 | 需要我作选择 | 检查缺少的选择或混类；不被低分平均掉 |
| 3 | 本类应保留逐次确认 | 暂停该范围免重复确认建议或约定的依赖，核实有效来源 |

评分是打断价值，不是风险、方案质量或执行许可。分别解释同一回复中的许可与评分：

- “同意，1 分”：在请求所说明的范围内继续，另记实际反馈。
- “1 分”：只记反馈；动作缺许可时仍等待许可。
- “同意”：按范围继续，不计分也不追问。
- 未回复：不推定同意或分数，其他独立已授权工作继续。
- “不做，0 分”：不执行，保留反馈；该样本不支持免重复确认建议。
- “以后这类别问”等明确指令：单独核实范围和效力，不从分数推断。只澄清影响执行的真实歧义。

## 记录、去重与建议

有真实反馈需要归并时才使用私有单文件台账；建议位置为 `%LOCALAPPDATA%/ai-agent-dotfiles.feedback/approval-feedback.md`，实际先核实本机可写性和写入授权。不要仅为加载 Skill 创建空台账。不进 Git、Skill 目录、生成物、部署状态或 config-sync；不存凭据、机器标识及完整会话。

单一记录者只保留五组信息；其他会话提供最小摘要，不并发改台账：

| 字段组 | 内容 |
|---|---|
| 关联 | 请求短编号、独立任务引用、项目与客户端短名 |
| 范围 | 类别一行、相对已有授权的变化；必要时附决策类型 |
| 用户输入 | 实际评分或未评分、本次许可／否定、最小来源引用 |
| 计数 | 独立性、去重或排除原因、反例；不能证明独立就不计阈值 |
| 建议跟踪 | 收集／待建议／已提出／暂缓／暂停及原始授权或修订来源、最后核实点 |

样本单位为独立任务中的一次用户判断。同任务的重试、拆步骤、跨会话继续只计一份；重复提交去重。保留原始反馈，同任务后续 2／3 分或否定执行优先阻止其支持建议。台账写入失败不阻塞已获准工作；未可靠保存的反馈不计阈值，不为补记发确认。

同一明确范围的 **三个独立任务均有真实 0–1 分、本次许可无冲突，且期间无 2–3 分或未解决反例／规则冲突**，才提出一次窄范围后续授权建议。不要平均分、回填历史分、把重试拆成样本或挑掉高分。反例先查是否混类；收窄须保留原证据，按新范围重新积累。暂缓／拒绝后不反复建议，除非用户重提或范围实质改变。

建议列实际项目／环境、客户端、动作／对象、数据／目的地、预算、例外、通知、期限或结束条件、撤销方式和授权保存位置。达标仅产生建议，不开始执行未来动作。用户直接明确授权不必先采满三份评分；持久化规则必须另有对应写入许可，正式入口写成并读回后才能依赖。

## 连续交付与偏好

同一协议可用于阶段衔接、有限失败恢复、等价方案、工具与并行安排、检查后的处置、预算内资源及通知。既有授权覆盖的实现、检查和直接相关修复连续推进；无关问题记录后续，不扩大交付，不减少必需门禁。

已明确的“优先复用、最小改动”等偏好按适用范围使用；低分或一次成功不证明技术偏好。可提出偏好修订建议，跨任务保存前给精确差异并取得相应授权。验收、返工、费用和用户纠正是客观结果，未知就留未知，不换算成用户评分，不增加阶段问卷。

恢复先确认是否已生效；结果未知先读回，不盲目重试。仅在原许可、预算、副作用和允许重试次数内恢复。付费调用须有涵盖实际调用、累计总额、单次上限、轮次和停止条件的明确许可；不可靠的预算不支持继续付费。正常 503／执行故障不算安全拒绝或审批反例。

## Git 与长期规则

提交、普通推送、合并分别核实许可；不因低分自动执行。已有规则允许的提交／推送照常完成，不以本 Skill 或台账为新门槛。准备执行这些动作时按 [workflows.md 的 Git 链](references/workflows.md#git-链)核实实际目标、最新检查、审查及读回；无需读取无关案例。

旧规则长期修订可以在发现根因后立即提出，无需等三份评分。获准后只改真正源文件和精确条款，保留个人覆盖与其他 WIP；生成物、live 根及全局配置走其现有构建／部署流程。项目内授权不扩展到全局。系统／开发者限制或平台硬确认没有可由本 Skill 修改的入口时，准确说明限制。

## 生效、撤销与失败

每个下一动作核实当前有效来源、范围和撤销状态；复用仍有效的相关证据，不全量重读无关文件。无可核实来源就不依赖自动处理；台账与缓存不续权，也不默认跨项目／平台／客户端迁移。

用户要求“以后问我”、出现 2／3 分反例或范围不符时，立即暂停后续动作依赖该范围约定并核实来源。0／1 分不会自行恢复权限。跨会话没有共同可读的当前正式来源时，不承诺同步生效或瞬时撤销；只适用于能核实约定的会话。

恢复依赖前须能核实反例的处理结论和当前明确授权；原许可已撤销时须有新的有效许可。不能凭后续低分、台账状态或 agent 自认问题解决恢复。

规则写入结果未知先读回；失败保持原有效边界。Skill 未加载时回到原有指令，不假装已启用，也不新增审批层。已开始／完成的动作先核实真实状态，补救另依权限，不承诺撤销规则能收回已发送数据或费用。必要结果和异常报告始终保留。
