# 经验沉淀

把当前任务中有证据的发现整理为下次能直接使用的简短经验。

1. 从本次任务已观察到的命令结果、检查或修复结果中筛选值得复用的发现。没有新经验时简短说明即可；未验证的猜测留在当前任务记录中。
2. 查找项目约定的知识文档和相关条目，优先原地补充或更正，合并重复内容；没有合适位置时，按项目目录约定创建最小必要文档。
3. 每条经验写清下面三项，按内容选用短段落或列表：
   - **适用条件**：相关项目、环境、版本或触发情形。
   - **有效做法**：已经奏效的命令或处理方式，以及必要的原因。
   - **验证依据**：本次实际检查及观察结果；有稳定记录时附相对路径。
4. 遇到反证时更新原条目的适用条件或撤下失效结论。只在需要消除疑点时补做范围内的必要检查，不为总结经验重复整套测试。
5. 交付时简述沉淀内容和文档位置；没有落盘时如实说明。

项目特有经验留在项目文档；通用流程只有在本次授权包含共享 skill 维护时才提升，并保留证据的适用范围。经验是事实参考，不改变项目规则或操作权限。

只使用当前任务可见的证据，不扫描历史会话或启动额外模型调用。文档不包含凭据、机器私有路径或会话原文；命令使用相对路径和环境变量占位符。
