# Grill Me / 拷问我

- **先查再问：** 优先从当前对话读取已知事实；在被允许且相关的范围内直接查证具体代码、配置或文档文件，**能自行查证的客观事实绝不向用户发问**。不做宽泛或隐私搜索，也不扩展到无关工作。
- **每轮只定一题：** 每次仅选一个未决决策，优先最阻塞后续工作的依赖项；无依赖顺序时选影响最大的一项。用户选择跳过、改题或结束即照办，不重复追问已定事项。
- **正文与卡片职责分离：** 正文只用 2–4 句简洁陈述句交代「已核实事实 + 本轮推荐方案与依据 + 备选取舍」，**正文不出现任何问句，也不加「Decision/问题」等重复标题**。唯一问题和选项全部放在原生 Ask 卡片内。
- **原生 Ask 卡片规范：** 每轮调用当前模式可用的原生 Ask 工具（默认模式用 `request_user_input_async`，计划模式可用 `request_user_input`）。卡片只含一个问句，给出 2–3 个可点选选项；推荐项列在首位并标明「（推荐）」或工具要求的 `(Recommended)`，每项附一句理由或取舍（工具仅支持字符串字段时直接写入选项文本），并保留自由输入。工具不可用时先说明原因，仅用户同意后改用文字访谈（文字模式整条回复同样只含一个问句）。
- **异步等待与异常止损：** 卡片发出后必须等待用户真实提交；`accepted`、界面预选和超时均不是答复。桌面端异步 Ask 仅在当前回合进行中可答，收到 `accepted` 后保持回合打开，严禁发 final（含「等你选择」等收尾）；用可被新输入唤醒的分段安静等待（如 `clock.sleep`）持续等到真实提交或改题/跳过/结束指示，再承接实际选择（含非推荐项）推进下一问。若等待工具本身不可用或连续报错，不改用 shell `sleep` 死等，也不伪造或推断答复，如实向用户说明原因并确认后续方式。
- **本地追问维度：** 参考 GSD 提问思路（见同目录 `LICENSE-GSD.txt`），按四维自检下一处未决分歧：① 谁用与核心目标/非目标；② 一次典型使用路径与关键接口；③ 不可逆取舍、边界条件与失败处理；④ 可观察的完成判据。用户已讲清的直接沿用，问到足以无歧义推进即收束，不逐条念清单。
- **五项交接总结：** 决策落定或访谈结束时，固定输出紧凑五项总结：**目标与非目标**、**已定决策与依据**、**关键约束与边界**、**可观察验收条件**、**剩余未知与风险**。用户已要求推进时直接将结论交给执行方；访谈本身不启动团队。
- **完全独立：** 本技能不依赖其他技能、包、团队或委派。
